## 5. 详细方案（Top 5 高优建议）

### 方案 H1: Milvus 连接池复用

**现状问题：** `vector.py` 中 `_milvus_search()` 每次搜索新建 `MilvusClient`，`memory_manager.py` 中 `LongTermMemoryManager.client` 属性也每次都创建新连接。每个用户问题触发向量检索时都多花 50-200ms 建立连接。

**改动方案：** 在 `__init__` 中创建一次 client 并复用。

> `src/retriever/vector.py` — VectorSearchMixin 类中

```python
# 现有代码（每次搜索新建连接）
def _milvus_search(self, query: str, top_k: int):
    client = MilvusClient(uri=Config.MILVUS_URI, timeout=Config.MILVUS_TIMEOUT)
    ...

# 改为：实例属性，__init__ 时创建
def __init__(self):
    self._milvus_client = None
    
@property
def _client(self):
    if self._milvus_client is None:
        try:
            self._milvus_client = MilvusClient(uri=Config.MILVUS_URI, timeout=Config.MILVUS_TIMEOUT)
        except Exception:
            self._disabled_vector_backends.add("milvus")
    return self._milvus_client
```

**风险：** Milvus 连接断开后需处理重连逻辑，建议加 `try/except` 捕获非可用状态时重新创建。

---

### 方案 H2: Embedding 模型全局单例

**现状问题：** `HybridRetriever` 和 `LongTermMemoryManager` 各自独立加载完全相同的 `SentenceTransformer` 模型，内存中出现两份（~2.4GB），首次加载也要重复等待。

**改动方案：** 抽取全局模型加载器，两个模块共享一个实例。

> 新建 `src/utils/embedding_loader.py`

```python
import functools
from sentence_transformers import SentenceTransformer
from src.config import Config

@functools.lru_cache(maxsize=1)
def get_embedding_model():
    """全局唯一的 embedding 模型单例"""
    return SentenceTransformer(Config.EMBEDDING_MODEL_PATH, device="cpu")
```

然后在 `vector.py` 和 `memory_manager.py` 中统一调用 `get_embedding_model()` 替换各自的 `_load_embedding_model()`。

---

### 方案 H3: 开启答案缓存

**现状问题：** `ENABLE_ANSWER_CACHE=false` 默认关闭，多轮对话中即使相同问题也每次都完整走检索+LLM 流程。

**改动方案：** 修改 `src/config.py` 第 96 行默认值。

```python
# 修改前
ENABLE_ANSWER_CACHE = os.getenv("ENABLE_ANSWER_CACHE", "false").lower() == "true"

# 修改后
ENABLE_ANSWER_CACHE = os.getenv("ENABLE_ANSWER_CACHE", "true").lower() == "true"
```

**风险：** 缓存 TTL 为 30 秒，对于动态数据场景需要注意。当前适用于招股说明书静态文档场景，不会有过期问题。

### 方案 H4: 冷启动预热

**现状问题：** 系统初始化只构建 BM25 索引，embedding 模型惰性加载。第一个用户请求要承受模型加载（2-5 秒）+ LLM 首次连接，总延迟 5-8 秒。

**改动方案：** 在 `initialize_project_knowledge_base()` 末尾增加后台预热。

> `src/rag_engine/initializer.py` — `InitializationMixin` 类中

```python
import threading

def initialize_project_knowledge_base(self):
    # ... 现有初始化逻辑 ...
    
    # 后台预加载 embedding 模型和 LLM 连接
    def _warmup():
        try:
            # 预加载 embedding 模型
            if hasattr(self, 'vector_store'):
                _ = self.vector_store._load_embedding_model()
            # 预建立 LLM 连接（发一个简单请求）
            if hasattr(self, 'llm_engine') and self.llm_engine.client:
                self.llm_engine.client.models.list()
        except Exception:
            pass  # 预热失败不影响主流程
    
    threading.Thread(target=_warmup, daemon=True).start()
    # ... 返回 init_result ...
```

### 方案 H5: 查询预处理 LRU 缓存

**现状问题：** `_expand_query()`（同义词扩展）和 `_tokenize()`（分词）每个搜索请求都重复执行。`_keyword_boost()` 长达 138 行，包含大量字符串查找。

**改动方案：** 对查询词做 LRU 缓存。

> `src/retriever/query.py` — `QueryProcessingMixin` 类中

```python
import functools

class QueryProcessingMixin:
    def __init__(self):
        self._expand_query = functools.lru_cache(maxsize=256)(self._expand_query_impl)
        self._tokenize = functools.lru_cache(maxsize=256)(self._tokenize_impl)
    
    def _expand_query_impl(self, query: str) -> str:
        # ... 现有同义词扩展逻辑 ...
    
    def _tokenize_impl(self, text: str) -> List[str]:
        # ... 现有分词逻辑 ...
```

**注意：** `lru_cache` 要求参数可哈希，确保 `query` 是普通字符串即可。
