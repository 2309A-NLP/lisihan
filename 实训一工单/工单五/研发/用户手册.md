# PDF招股说明书智能问答系统用户手册

工单编号：人工智能NLP-RAG-基于PDF文档的问答系统

## 1. 系统能做什么

本系统用于对招股说明书 PDF 进行智能问答。你可以把 PDF 放入 `data/` 目录，启动系统后在网页中直接提问。

系统当前支持：

- MinerU PDF 正文解析
- MinerU PDF 表格解析
- 招股说明书固定信息直答
- BM25 + Milvus 混合检索
- Redis 保存最近 20 条短期对话
- Milvus 保存长期优质问答
- 工单问题批量评估

典型可问问题：

- 法定代表人是谁？
- 注册资本是多少？
- 公司参与制定了哪个技术标准？
- 来自军用领域的收入分别是多少？
- 军用领域收入占主营业务收入的比重是多少？
- 电子信息行业的上游涉及哪些企业？
- 公司在哪个领域已经成为重要供应商？

## 2. 使用前准备

### 2.1 放入 PDF

将需要问答的 PDF 文件放到：

```text
data/
```

例如：

```text
data/招股说明书1.pdf
```

### 2.2 启动 Redis 和 Milvus

项目依赖 Redis 和 Milvus：

- Redis：保存短期对话历史
- Milvus：保存长期记忆，并提供向量检索能力

如果使用项目自带 Docker 配置：

```powershell
docker compose up -d
```

确认端口：

```text
Redis  : localhost:6379
Milvus : localhost:19530
```

### 2.3 安装依赖

推荐使用项目自己的虚拟环境：

```powershell
cd C:\Users\freedom\Desktop\问答系统5
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 3. 启动系统

### 3.1 Web 页面模式

```powershell
cd C:\Users\freedom\Desktop\问答系统5
.\.venv\Scripts\python.exe main.py
```

启动后访问页面：

```text
http://localhost:8502
```

说明：  
如果误用了其他项目的 Python 环境启动，`main.py` 会自动切回本项目 `.venv`。

### 3.2 命令行模式

```powershell
.\.venv\Scripts\python.exe main.py --mode cli
```

命令行模式会运行内置评测问题，适合调试和验收。

## 4. 页面功能说明

### 4.1 配置面板

页面左侧会显示：

- 当前检索方式
- 索引名称
- 召回条数
- 知识库初始化状态

可以执行：

- 重新解析并构建混合检索索引
- 查看最近 20 条短期对话历史
- 查看长期记忆
- 运行工单问题评估

### 4.2 检索模式

页面支持选择：

- 混合检索
- BM25 检索
- 向量检索

一般建议使用默认的“混合检索”。

精确问题会自动走快速路径，避免慢查询。例如：

- 法定代表人
- 注册资本
- 技术标准
- 上游/下游
- 军用领域收入
- 收入比重

### 4.3 提问

在页面底部输入问题即可。

示例：

```text
法定代表人是谁？
```

```text
报告期内，武汉兴图新科电子股份有限公司来自军用领域的收入分别是多少？
```

```text
根据武汉兴图新科电子股份有限公司招股意向书，电子信息行业的上游涉及哪些企业？
```

### 4.4 查看调试信息

回答下方可展开调试信息，通常包括：

- 检索模式
- 命中的片段
- 相关性分数
- 回答来源
- 响应耗时

如果回答不符合预期，优先查看命中的 PDF 片段是否正确。

### 4.5 短期记忆

点击：

```text
查看最近 20 条短期对话历史
```

系统会从 Redis 中读取最近对话。

如果提示 Redis 不可用，请检查：

- Redis 是否启动
- `redis` Python 包是否安装
- `REDIS_URL` 是否正确

### 4.6 长期记忆

点击：

```text
查看长期记忆
```

系统会从 Milvus 读取已保存的优质问答。

当你点击回答反馈中的“有帮助”时，系统会尝试把该问答写入 Milvus 长期记忆。

如果提示 Milvus 不可用，请检查：

- Milvus 是否启动
- `pymilvus` Python 包是否安装
- `MILVUS_URI` 是否正确

## 5. PDF 解析输出

系统启动或点击“重新解析并构建混合检索索引”后，会解析 `data/` 中的 PDF。

解析结果输出到：

```text
mineru_output/
```

常见文件：

```text
mineru_output/招股说明书1/auto/招股说明书1.md
mineru_output/招股说明书1/auto/招股说明书1_content_list.json
mineru_output/招股说明书1_chunks.json
mineru_output/招股说明书1_metadata.json
```

其中：

- `*.md`：MinerU 原始 Markdown，必须保留
- `*_content_list.json`：MinerU 原始结构化内容，必须保留
- `*_chunks.json`：适配给项目 RAG 链路使用的正文、表格、页码、位置、分块信息
- `*_metadata.json`：公司名称、法定代表人、注册资本、成立日期、注册地址

这些文件可用于人工复核。

默认解析配置为 MinerU `pipeline` 后端和 ModelScope 模型源。也可以手动批量解析：

```powershell
.\.venv\Scripts\python.exe run_mineru_wsl.py data --output-dir mineru_output
```

或显式传入两个 PDF：

```powershell
.\.venv\Scripts\python.exe run_mineru_wsl.py data\招股说明书1.pdf data\招股说明书2.pdf --output-dir mineru_output
```

## 6. 固定信息问题

以下问题会优先使用元数据，不走普通检索：

| 问题 | 返回 |
| --- | --- |
| 法定代表人是谁？ | 程家明 |
| 注册资本是多少？ | 5,520万元 |
| 公司成立日期是什么？ | 2004年6月17日 |
| 注册地址在哪里？ | 湖北省武汉东湖新技术开发区关山大道1号软件产业三期A3栋8层 |

这样可以避免表格、银行信息或中介机构信息干扰答案。

## 7. 内置优化问题

系统已针对招股说明书常见问题做了规则优化：

### 7.1 军用领域收入

用户问：

```text
报告期内，武汉兴图新科电子股份有限公司来自军用领域的收入分别是多少？
```

系统会自动改写为：

```text
直接和间接向国防客户的销售额合计分别是多少
```

返回：

```text
6,464.51万元、14,414.16万元、18,780.67万元
```

### 7.2 军用领域收入比重

系统会区分“金额”和“比重”：

- 问收入金额：返回万元
- 问占比/比重：返回百分比

### 7.3 上游企业

系统优先命中“行业上下游情况”相关片段，避免返回会计师声明等无关内容。

### 7.4 重要供应商

系统优先命中：

```text
兴图新科目前已经成为国防军队视频指挥领域的重要供应商
```

返回：

```text
国防军队视频指挥领域
```

## 9. 常见问题

### 9.1 页面提示知识库未初始化

检查：

- `data/` 目录是否有 PDF
- PDF 文件是否可打开
- 依赖是否安装完整
- 日志 `logs/app.log` 是否有解析错误

然后点击：

```text
重新解析并构建混合检索索引
```

### 9.2 Redis 短期记忆不可用

检查 Redis 服务：

```powershell
netstat -ano | Select-String ":6379"
```

确认依赖：

```powershell
.\.venv\Scripts\python.exe -m pip show redis
```

### 9.3 Milvus 长期记忆不可用

检查 Milvus 服务：

```powershell
netstat -ano | Select-String ":19530"
```

确认依赖：

```powershell
.\.venv\Scripts\python.exe -m pip show pymilvus
```

### 9.4 回答内容明显跑偏

建议按顺序检查：

1. 展开调试信息，看命中片段是否正确
2. 查看 `mineru_output/*_chunks.json` 是否包含正确原文
3. 检查问题是否属于固定字段，必要时补充元数据抽取规则
4. 检查 `src/retriever.py` 中是否需要添加关键词加权
5. 检查 `utils/llm_engine.py` 中是否需要添加规则抽取或后处理

### 9.5 PDF 表格识别不理想

系统默认使用 MinerU 抽取表格。复杂合并单元格可能需要人工复核。

可查看：

```text
mineru_output/*_chunks.json
mineru_output/<PDF文件名>/auto/*_content_list.json
```

确认表格块是否被正确提取。

## 10. 文件说明

| 文件/目录 | 作用 |
| --- | --- |
| `main.py` | 程序启动入口 |
| `app.py` | Streamlit 页面 |
| `data/` | PDF 原文目录 |
| `mineru_output/` | MinerU 原始输出和项目解析结果目录 |
| `pdf_parser/` | PDF 解析模块 |
| `src/rag_engine.py` | RAG 主流程 |
| `src/retriever.py` | BM25 + Milvus + RRF 检索 |
| `src/memory_manager.py` | Redis 和 Milvus 记忆 |
| `utils/llm_engine.py` | LLM 调用、规则抽取、答案后处理 |
| `logs/app.log` | 系统日志 |

## 11. 注意事项

- 不要删除 `data/` 中的 PDF，除非确认不再需要该知识库
- 删除 `mineru_output/` 后，需要重新解析 PDF
- 当前系统不再使用 ChromaDB
- 当前系统默认使用 MinerU
- MinerU 原始 `.md` 和 `content_list.json` 缺失时，系统会报错并提示检查 MinerU 环境
- 固定字段问题优先走元数据，不依赖 LLM
- 精确问题会优先走快速路径，以保证响应速度
