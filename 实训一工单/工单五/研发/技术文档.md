# PDF招股说明书智能问答系统技术文档

工单编号：人工智能NLP-RAG-基于PDF文档的问答系统

## 1. 项目概述

本项目面向招股说明书 PDF 文档构建智能问答系统，重点处理以下场景：

- 招股说明书正文问答
- 财务、股东、发行概况等表格内容解析
- 章节化长文档分块
- 固定元数据问题直答，如法定代表人、注册资本、成立日期、注册地址
- BM25 + Milvus 向量检索 + RRF 融合
- Redis 保存最近 20 条短期对话
- Milvus 保存长期优质问答记忆

系统入口：

- `main.py`：统一启动入口，支持 Web 模式和 CLI 模式
- `app.py`：Streamlit 前端页面
- `pdf_parser/`：PDF 解析与分块模块
- `src/rag_engine.py`：RAG 主流程编排

## 2. 当前架构

系统整体流程如下：

1. 读取 `data/` 目录中的 PDF 文件
2. 默认调用 WSL 中的 MinerU pipeline 解析 PDF
3. MinerU 输出原始 `.md` 和 `content_list.json`
4. 项目将 MinerU 结果适配为原有 `*_chunks.json`
5. 提取文档固定元数据
6. 构建 BM25 索引
7. 对普通语义问题使用 Milvus 向量检索辅助召回
8. 使用 RRF 对 BM25 和向量检索结果融合排序
9. 对精确问题使用快速路径跳过向量检索
10. 使用规则抽取、元数据直答或 LLM 生成答案
11. 使用 Redis 保存短期对话，使用 Milvus 保存长期优质问答

## 4. 核心模块

### 4.1 PDF 解析模块

位置：`pdf_parser/`

当前默认解析流程：

- `parser.py` 默认使用 `Config.PDF_PARSER_BACKEND = "mineru"`
- `mineru_backend.py` 调用 MinerU，并强制检查 `.md` 和 `content_list.json`
- `mineru_backend.py` 将 MinerU 输出适配成项目原有 `*_chunks.json`
- `metadata_extractor.py` 从招股说明书前若干页抽取固定字段
- `text_extractor.py`、`table_extractor.py`、`chunk_merger.py` 保留给显式 `--backend local` 场景

解析输出包含：

- `source_file`
- `source_path`
- `page_count`
- `chunk_count`
- `table_count`
- `image_count`
- `parser_backend`
- `mineru_markdown`
- `mineru_content_list`
- `document_metadata`
- `chunks`

同时会生成：

```text
mineru_output/招股说明书1/auto/招股说明书1.md
mineru_output/招股说明书1/auto/招股说明书1_content_list.json
mineru_output/招股说明书1_chunks.json
mineru_output/招股说明书1_metadata.json
```

如果 MinerU 未生成 `.md` 或 `content_list.json`，解析会直接报错，不再静默切回本地解析。

### 4.2 文档元数据抽取

位置：`pdf_parser/metadata_extractor.py`

用于解决唯一固定字段问题，避免依赖检索和 LLM 猜测。

当前抽取字段：

```python
{
    "company_name": "武汉兴图新科电子股份有限公司",
    "legal_representative": "程家明",
    "registered_capital": "5,520万元",
    "establishment_date": "2004年6月17日",
    "registered_address": "湖北省武汉东湖新技术开发区关山大道1号软件产业三期A3栋8层"
}
```

RAG 回答时会优先使用元数据回答以下问题：

- 法定代表人是谁
- 注册资本是多少
- 公司成立日期是什么
- 注册地址在哪里
- 公司名称是什么

### 4.3 检索模块

位置：`src/retriever.py`

当前检索策略：

- BM25：主召回方式，适合招股说明书中的精确关键词问题
- Milvus：向量检索，用于普通语义问题辅助召回
- RRF：融合 BM25 和向量召回结果
- 快速路径：对精确问题跳过向量检索，降低响应时间

ChromaDB 已移除，项目不再依赖 `chromadb` 或 `chroma_db` 文件夹。

精确问题快速路径包括：

- 法定代表人
- 注册资本
- 技术标准
- 上游/下游
- 重要供应商
- 军用领域收入
- 收入占比/比重
- 募集资金

### 4.4 Query 改写

位置：`src/rag_engine.py`

用于将用户自然表达映射到招股书标准字段。

示例：

```text
用户问题：
报告期内，武汉兴图新科电子股份有限公司来自军用领域的收入分别是多少？

改写后：
直接和间接向国防客户的销售额合计分别是多少
```

这样可以避免系统把“直接军方收入”和“间接军方收入”分开回答。

### 4.5 问题分类

位置：`utils/question_classifier.py`

问题类型：

- `numeric`：金额、数量、注册资本等
- `percentage`：占比、比重、比例、百分比
- `entity`：实体、机构、人员、领域、标准等

分类结果会影响：

- 是否跳过长期记忆
- 是否走精确检索
- 使用哪个 Prompt
- 是否启用本地规则抽取

### 4.6 回答生成与后处理

位置：`utils/llm_engine.py`

回答优先级：

1. 文档元数据直答
2. 长期记忆命中
3. 检索上下文规则抽取
4. LLM 生成
5. 离线兜底抽取

后处理负责：

- 清除表格竖线和残片
- 过滤银行、授信、合同等无关上下文
- 固定法定代表人输出为姓名
- 固定注册资本输出为金额
- 军用领域收入输出合计值
- 比重问题限制输出百分比

### 4.7 记忆模块

位置：`src/memory_manager.py`

短期记忆：

- 使用 Redis
- 保存最近 20 条用户和助手消息
- 默认 TTL 来自 `Config.REDIS_SESSION_TTL`

长期记忆：

- 使用 Milvus
- 用户点击“有帮助”后，将优质问答写入长期记忆
- RAG 在非精确问题上会尝试搜索长期记忆

精确问题会跳过长期记忆，避免首次加载 embedding 模型导致响应变慢。

## 5. 配置说明

位置：`src/config.py`

主要配置：

```python
PDF_DIR = "./data"
PDF_PARSER_BACKEND = "mineru"
PDF_PARSE_OUTPUT_DIR = "./mineru_output"
MINERU_OUTPUT_DIR = "./mineru_output"
MINERU_BACKEND = "pipeline"
MINERU_MODEL_SOURCE = "modelscope"
COLLECTION_NAME = "pdf_documents"

BM25_K = 6
VECTOR_K = 4
RRF_K = 30
BM25_RRF_WEIGHT = 3.0
VECTOR_RRF_WEIGHT = 1.0
FINAL_K = 3
SKIP_VECTOR_FOR_EXACT_QUERIES = True

MILVUS_URI = "http://localhost:19530"
REDIS_URL = "redis://localhost:6379/0"
SHORT_MEMORY_LIMIT = 20

LLM_MODEL = "deepseek-ai/DeepSeek-V4-Flash"
LLM_TIMEOUT = 2.5
LLM_CONTEXT_MAX_CHARS = 3600
```

环境变量可覆盖上述配置。

## 6. 运行方式

### 6.1 启动 Redis / Milvus

如果使用本项目的 Docker 配置：

```powershell
docker compose up -d
```

需要确认：

- Redis：`localhost:6379`
- Milvus：`localhost:19530`

### 6.2 安装依赖

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 6.3 启动 Web 页面

```powershell
.\.venv\Scripts\python.exe main.py
```

`main.py` 会检测是否误用了其他项目虚拟环境，并自动切回本项目 `.venv`。

### 6.4 命令行模式

```powershell
.\.venv\Scripts\python.exe main.py --mode cli
```

### 6.5 批量运行 MinerU

解析 `data/` 目录下所有 PDF：

```powershell
.\.venv\Scripts\python.exe run_mineru_wsl.py data --output-dir mineru_output
```

显式解析两个 PDF：

```powershell
.\.venv\Scripts\python.exe run_mineru_wsl.py data\招股说明书1.pdf data\招股说明书2.pdf --output-dir mineru_output
```

默认配置为 MinerU `pipeline` 后端和 ModelScope 模型源，不会默认走 Hugging Face VLM 下载。

## 8. 日志与排查

日志位置：

```text
logs/app.log
```

常见问题：

- Milvus 不可用：检查 `localhost:19530` 是否监听，确认 `pymilvus` 已安装
- Redis 不可用：检查 `localhost:6379` 是否监听，确认 `redis` 包已安装
- 解析结果不对：查看 `mineru_output/*_chunks.json`、`mineru_output/*_metadata.json` 以及对应 PDF 的原始 `.md`
- MinerU 未生成原始 Markdown：检查 `mineru_output/<PDF文件名>/auto/*.md` 和 `*_content_list.json`
- 回答跑偏：优先检查检索 Top 片段，再检查 `llm_engine.py` 中的规则抽取和后处理

## 9. 重要说明

- MinerU 是当前默认 PDF 主解析流程
- MinerU 原始 `.md` 和 `content_list.json` 必须保留，后续排查优先查看这些文件
- `src/pdf_parser.py` 已删除，当前只使用 `pdf_parser/` 包
- ChromaDB 已删除，当前只保留 Milvus 向量检索
- 固定字段问题优先使用元数据，不再依赖检索
- 精确问题优先走 BM25 快速路径，普通语义问题再使用 Milvus + RRF
