## 1. 已完成的优化

### 1.1 新增优化引擎

| 序号 | 优化项 | 文件 | 说明 |
| --- | --- | --- | --- |
| 1 | **RAGEngineOptimized 类** | `src/rag_engine_optimized.py` | 继承工单八 `RAGEngine`，覆盖 `ask()` 和 `_build_context()` 方法，在不破坏原有 11 级流水线的前提下注入优化逻辑。`ask()` 中增加：`_normalize_sample_question`（Unicode 修复）→ `_merge_optimized_retrieval_config`（合并默认优化配置）→ `_optimized_retrieval_mode`（智能模式选择） |
| 2 | **兼容工单八接口** | `src/rag_engine_optimized.py` | `RAGEngineOptimized.ask()` 签名与 `RAGEngine.ask()` 完全兼容，所有工单八的查询路径（缓存、多模态、负向、元数据、长期记忆等）均保留，新增优化仅在检索+上下文构建阶段生效 |
| 3 | **默认优化检索配置** | `src/rag_engine_optimized.py` | `DEFAULT_OPTIMIZED_RETRIEVAL_CONFIG` 经过工单七/八数据调参：BM25=0.72 vs 向量=0.28（金融文档以精确匹配为主）、match_type=fuzzy（优先模糊匹配兜底）、reranker=adaptive（自适应）、fusion=weighted（加权平均替代 RRF） |

### 1.2 上下文选择优化

| 序号 | 优化项 | 说明 |
| --- | --- | --- |
| 4 | **OptimizedContextSelector** | **全新上下文选择器**，替代 `ContextMixin._build_context` 的简单截断逻辑。核心包含三个机制： |
| 5 | **① 去重（Deduplication）** | 按 `source_file + page + chunk_id` 精准去重，去重键无此三要素时回退到内容前 180 字符的归一化哈希。解决工单八中同一证据因 BM25 和向量检索同时命中而重复进入上下文的问题 |
| 6 | **② 加权重排（Weighted Rerank）** | `_score()` 方法综合 6 维评分：基础检索分数 + 排名衰减（1/(rank+1)） + 问题关键词重叠度（每词 +0.35） + 数值触发加分（含数字 +1.2） + 关系触发加分（图谱/关联 +1.5） + 图谱来源加分（+0.35） - 模糊自动降级扣分（-0.2） - 多模态标记扣分（-1.0） |
| 7 | **③ 预算打包（Budget Packing）** | 按分数降序选择上下文，当累计字符数超过 `context_budget_chars`（默认 2200）或达 `final_k`（默认 4）时截断。低分但信息量大的片段通过截断保留前缀，确保关键信息不丢失 |

### 1.3 检索策略优化

| 序号 | 优化项 | 文件 | 说明 |
| --- | --- | --- | --- |
| 8 | **匿名银行题禁用图图谱** | `src/rag_engine_optimized.py` | `_optimized_retrieval_mode()` 方法：对于包含"xx银行 董事长致辞"等标题目时自动切换到 `hybrid` 模式（仅文本检索），避免招股说明书的图谱关系污染年报答案 |
| 9 | **检索候选数增加** | `src/rag_engine_optimized.py` | `candidate_k` = 5（相比工单八的 TOP_K=3 增加 67%），通过更多候选保证召回全面性，再由 OptimizedContextSelector 精选 |
| 10 | **时间保护机制** | `src/rag_engine_optimized.py` | `max_retrieval_seconds` = 5.0s：检索超时后自动截断图谱分支，只保留非图谱上下文进入生成阶段。避免复杂图谱查询拖慢整体响应 |
| 11 | **自适应重排** | `src/retriever/reranker.py` | 优化配置默认使用 `adaptive` 重排器，结合用户历史反馈动态调整排序权重，长期运行时准确率递增 |

### 1.6 RAGAS 评估体系

| 序号 | 优化项 | 文件 | 说明 |

| 17 | **RAGAS 评估框架集成** | `evaluate_with_ragas.py` | 引入业界标准 RAGAS 评估框架，自动评估 `context_precision` 和 `context_recall` 两项核心指标。支持真实 RAGAS（需 LLM）和本地兼容评估器双模式 |
| 18 | **RAGAS 环境自动配置** | `evaluate_with_ragas.py` | `configure_ragas_environment()` 自动从 `.env` 读取 LLM 配置并映射到 OpenAI-compatible 环境变量，无需手动配置 |
| 19 | **本地兼容评估器** | `evaluate_with_ragas.py` | `local_context_metrics()` 实现与 RAGAS 兼容的本地评估：基于问题关键术语、参考答案术语与检索上下文的重叠度计算 precision 和 recall。当 RAGAS LLM 不可用时自动降级 |
| 20 | **参考 QA 自动提取** | `evaluate_with_ragas.py` | `parse_reference_qa()` 自动从 `sample_questions.pdf` 提取"问题/参考答案"对，支持 PyMuPDF 和 pypdf 双后端。使用正则解析和模糊匹配（SequenceMatcher ≥ 0.62）对齐 |
| 21 | **验收指标定义** | `evaluate_with_ragas.py` | 明确定义 3 项验收标准：context_precision ≥ 0.8、context_recall ≥ 0.9、average_response_time ≤ 3.0s。`evaluate_records()` 自动输出达标状态 |
| 22 | **评估结果持久化** | `evaluate_with_ragas.py` | 评估结果保存为结构化的 JSON（含 summary + details 两级），summary 包含整体指标和达标状态，details 包含每题明细 |
| 23 | **NFKC 文本归一化** | `evaluate_with_ragas.py` | `normalize_text()` 使用 Unicode NFKC 规范化，处理全半角、特殊空格（\\u00a0）等 PDF 常见文本问题 |

## 3. 优化效果对比

### 3.1 工单八（基线） vs 工单九（优化）

| 对比项 | 工单八（基线） | 工单九（优化） | 提升方向 |
| --- | --- | --- | --- |
| 引擎 | RAGEngine（Mixin 架构） | RAGEngineOptimized（继承+覆盖） | 兼容性 + 增量优化 |
| 检索权重 | BM25=0.5~0.65 / 向量=0.35~0.5 | BM25=0.72 / 向量=0.28（固定） | 金融精确匹配优先 |
| BM25 匹配 | phrase→auto_fallback→fuzzy | fuzzy（直接启用） | 减少一次降级开销 |
| 重排策略 | LLM | adaptive（自适应） | 长期更优 |
| 融合方式 | RRF | weighted（加权平均） | 权重直接可控 |
| 上下文选择 | 简单截断 | 去重→重排→预算打包（3 层） | 信息密度提升 |
| 候选→最终 | 6→3 | 5→4 | 召回更充分 |
| 上下文预算 | 1800 chars | 2200 chars | 更多信息入参 |
| 图谱深度 | auto | 1（固定） | 响应时间更稳定 |
| 查询扩展 | 静态同义词映射 | 静态 + 领域关键词扩展 | 召回更高 |
| 来源过滤 | 无 | 按题目类型限定 PDF | 答案更精准 |
| Unicode 修复 | 无 | ⻓→长、⻛→风归一化 | 检索稳定性 |
| 评估框架 | 内置评估器 | RAGAS + 本地兼容双模式 | 业界标准 |
| 参考集 | 14 题（招股书） | sample_questions.pdf（年报） | 场景扩展 |
| 优化对比 | 无 | 离线/实时双模式 + 对比表 | 可量化验证 |

### 3.3 核心建议

> **优先投入方向**：
