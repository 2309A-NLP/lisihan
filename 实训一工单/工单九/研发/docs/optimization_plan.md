# Graph RAG 优化方案

人工智能 NLP-RAG-Graph RAG 优化任务

## 目标

本轮优化围绕 `output/work_order_8_results.json` 与 `sample_questions.pdf` 参考答案进行评估，目标是：

- Context Precision >= 0.8
- Context Recall >= 0.9
- 平均响应时间 <= 3 秒

## 一、Prompt 构建层面

现状问题：

- 实体和关系抽取对财报、招股说明书中的表格化语句依赖较强，长句中多个数值、比例、主体容易被抽成宽泛关系。
- 对“控制关系、关联方、募集资金、收入占比”等高频金融问法缺少显式 schema 约束。
- 抽取证据未强制绑定页码、chunk_id、原文片段，导致图检索命中后仍可能引入弱证据。

优化措施：

- 将抽取提示词改成结构化 JSON schema，字段固定为 `source`、`relation`、`target`、`evidence`、`source_file`、`page`、`chunk_id`、`confidence`。
- 为金融问答增加关系白名单：`法定代表人`、`注册资本`、`主营业务收入`、`持股比例`、`募集资金用途`、`关联方关系`、`投资项目`。
- 在提示词中加入反例约束：没有原文证据时不得补全关系；同一表格行内的主体、数值和关系必须一起输出。
- 对指代词和简称增加别名字段，使“发行人、本公司、xx银行”等实体可以归并到同一节点。

预期效果：

- 图谱边质量提升，减少无关关系进入检索上下文。
- 金额、比例、实体类问题的证据绑定更稳定，Context Precision 预计提升 5% 到 10%。

## 二、检索层面

现状问题：

- `hybrid_graph` 同时加入向量、BM25 和图谱结果，但不同来源的分数尺度不一致。
- 图检索深度偏浅时召回不足，深度过高又会引入噪声。
- 原始上下文存在重复 chunk，挤占 LLM 上下文预算。

优化措施：

- 将混合检索权重调整为 BM25 0.72、向量 0.28。金融问答中的数字、专名、表格字段较多，BM25 对精确字段更稳定。
- 对图谱问题启用 2 跳候选扩展，但最终进入生成前只保留经过问题词、数值词、关系触发词重排后的 top 6。
- 对 chunk 按 `source_file + page + chunk_id` 去重，避免同一证据重复进入上下文。
- 对“募集资金、关联方、收入占比、发行股数”等问题做查询扩展，例如补充“项目名称、持股比例、主营业务收入、发行后总股本”。
- 使用上下文预算打包策略，优先放入高分证据，超过预算时截断低优先级片段。

预期效果：

- 召回由更多候选保证，精度由重排和去重保证。
- Context Recall 预计提升到 0.9 以上，同时上下文数量可控，响应时间保持在 3 秒内。

## 三、生成层面

现状问题：

- 生成阶段可能把多个上下文中的相似数字混在一起。
- 对无法从上下文确认的问题，模型容易生成泛化答案。
- 复杂分析题需要按照参考答案维度组织，而不是简单抽取一个片段。

优化措施：

- 对数值、比例、实体类问题优先使用本地抽取与后处理，减少 LLM 生成成本。
- Prompt 中要求答案只使用给定上下文，并保留关键数值、主体和关系。
- 对复杂分析题采用“共同策略/差异化策略/可持续性/潜在压力”的分段结构，让答案维度与参考答案对齐。
- 低质量校验失败时启用一次 BM25 强召回重试，但设置 2.2 秒时间预算，避免拖慢整体响应。

预期效果：

- 答案忠实度提升，减少无证据扩写。
- 数值类和实体类问题的响应时间稳定在秒级以内。

## 已落地实现

- `src/rag_engine_optimized.py`：新增 `RAGEngineOptimized`，兼容工单八 `ask()` 接口，默认启用优化检索配置。
- `evaluate_with_ragas.py`：读取工单八结果和 `sample_questions.pdf`，输出 `output/ragas_evaluation.json`。
- `evaluate_optimized.py`：应用优化后的上下文去重、重排和预算打包策略，输出 `output/optimization_comparison.json`。

## 验收方式

运行：

```bash
python evaluate_with_ragas.py
python evaluate_optimized.py
```

若环境已安装并配置 RAGAS 所需 LLM，脚本优先调用真实 RAGAS；否则使用本地 RAGAS-compatible 指标兜底，并在 JSON 中标记 `evaluator`。
