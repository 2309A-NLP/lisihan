## 1. 系统概述

本系统面向招股说明书 PDF 构建智能问答，核心升级为 **BM25 + 向量检索 + RRF 混合检索**，并增加了 **元数据直答**、**查询改写**、**Redis 短期记忆** 和 **Milvus 长期记忆** 等增强功能。

### 1.1 架构总览

```
┌──────────────────────────────────────────────────────────┐
│                      入口层                               │
│    main.py（自动检测虚拟环境 + CLI/Web入口）                │
│    app.py（Streamlit界面 + 检索模式/语言选择）              │
├──────────────────────────────────────────────────────────┤
│                      混合检索层                            │
│    retriever.py → HybridRetriever                         │
│      ├── BM25 Okapi（关键词精确召回）                      │
│      ├── Milvus 向量检索（语义辅助召回）                    │
│      └── RRF 融合排序（BM25权重3.0 + 向量权重1.0）         │
├──────────────────────────────────────────────────────────┤
│                      回答生成层                            │
│    rag_engine.py → RAGEngine                              │
│      ├── 元数据直答（法定代表人/注册资本等 <10ms）          │
│      ├── 长期记忆命中（Milvus 优质问答）                    │
│      ├── 查询改写（rewrite_query）                         │
│      └── 检索上下文 + LLM 生成                              │
│    llm_engine.py → LLMEngine                              │
│      ├── 规则抽取（_extract_answer_from_context）           │
│      ├── 在线 LLM 生成（OpenAI API）                       │
│      ├── 离线兜底（本地规则 + 句子匹配）                    │
│      └── 多语言输出（中/英）                                │
├──────────────────────────────────────────────────────────┤
│                      PDF 解析模块                           │
│    pdf_parser/ → 7个子模块                                │
│      ├── text_extractor.py（PyMuPDF文本）                  │
│      ├── table_extractor.py（pdfplumber表格）              │
│      ├── chunk_merger.py（块合并 + 段落聚合）               │
│      ├── filters.py（噪声过滤）                             │
│      ├── metadata_extractor.py（固定字段提取）              │
│      ├── mineru_wsl.py（WSL MinerU）                       │
│      └── main.py（解析总入口）                              │
├──────────────────────────────────────────────────────────┤
│                      记忆系统                              │
│    memory_manager.py                                       │
│      ├── RedisMemoryManager → 短期（最近20条对话）         │
│      └── LongTermMemoryManager → 长期（Milvus向量存储）    │
├──────────────────────────────────────────────────────────┤
│                      基础设施                              │
│    docker-compose.yml → Milvus(19530) + Redis(6379)       │
└──────────────────────────────────────────────────────────┘
```

### 1.2 数据流（完整链路）

```
用户放入 PDF → 解析（PyMuPDF+pdfplumber）→ 分块（段落/句子）
  → 提取元数据 → 构建 BM25 索引 → 写入 Milvus 向量

用户提问 → 问题分类 → 查询改写 → [元数据查?] → [长期记忆查?]
  → 混合检索（BM25 + 向量 + RRF）→ 上下文构建
  → [规则抽取?] → [LLM生成?] → 输出 + 写 Redis 短期记忆
```

## 4. 配置文件详解

### 4.1 核心配置（`src/config.py`）

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| **PDF & 解析** |
| `PDF_DIR` | `./data` | PDF 存放目录 |
| `PDF_PARSE_OUTPUT_DIR` | `./mineru_output` | 解析结果输出目录 |
| **检索参数** |
| `RETRIEVAL_BACKEND` | `hybrid` | 检索方式（hybrid/bm25/vector） |
| `BM25_K` | `6` | BM25 候选条数 |
| `VECTOR_K` | `4` | 向量检索候选条数 |
| `RRF_K` | `30` | RRF 融合参数 K 值 |
| `BM25_RRF_WEIGHT` | `3.0` | BM25 在 RRF 中的权重 |
| `VECTOR_RRF_WEIGHT` | `1.0` | 向量在 RRF 中的权重 |
| `FINAL_K` | `3` | 最终返回 Top-K 条 |
| `SKIP_VECTOR_FOR_EXACT_QUERIES` | `True` | 精确查询跳过向量检索 |
| **LLM 配置** |
| `LLM_MODEL` | `deepseek-ai/DeepSeek-V4-Flash` | 模型名称 |
| `LLM_TIMEOUT` | `2.5` | API 调用超时（秒） |
| `LLM_MAX_TOKENS` | `1024` | 最大输出 Token 数 |
| `LLM_CONTEXT_MAX_CHARS` | `3600` | 上下文最大字符数 |
| **Milvus 配置** |
| `MILVUS_URI` | `http://localhost:19530` | Milvus 连接地址 |
| `MILVUS_TIMEOUT` | `3` | 连接超时（秒） |
| `MILVUS_COLLECTION_LONG_TERM` | `long_term_memory` | 长期记忆集合名 |
| **Redis 配置** |
| `REDIS_URL` | `redis://localhost:6379/0` | Redis 连接地址 |
| `SHORT_MEMORY_LIMIT` | `20` | 短期记忆保留条数 |
| `REDIS_SESSION_TTL` | `86400` | 会话 TTL（秒，24h） |

> 所有配置项均可通过同名环境变量在 `.env` 中覆盖。

## 6. 记忆系统说明

### 6.1 Redis 短期记忆

- 自动保存每轮问答到 Redis
- 保留最近 20 条对话记录
- 24 小时自动过期
- Redis 不可用时不影响核心问答功能

查看方式：左侧面板 → [查看最近 20 条短期对话历史]

### 6.2 Milvus 长期记忆

- 用户点击"有帮助"后，自动将 QA 对向量化存入 Milvus
- 后续相似问题（余弦相似度 ≥ 0.8）直接返回长期记忆
- 精确问题（数值/百分比）会自动跳过长期记忆，避免首次加载模型拖慢响应
- Milvus 不可用时不影响核心问答功能

查看方式：左侧面板 → [查看长期记忆]

### 6.3 记忆优先级

```
回答优先级（从高到低）：
1. 文档元数据直答（法定代表人/注册资本等，<10ms）
2. 长期记忆命中（Milvus 余弦相似度 >= 0.8）
3. 检索上下文规则抽取（本地离线提取）
4. LLM 在线生成（OpenAI API）
5. 离线兜底（句子匹配 + 关键词评分）
```

## 8. 常见问题排查

### 8.1 Milvus 连接失败

```bash
# 检查 Milvus 是否运行
docker ps | findstr milvus

# 检查端口
netstat -ano | findstr ":19530"

# 重启服务
docker compose down
docker compose up -d
```

### 8.2 Redis 连接失败

```bash
# 检查 Redis 是否运行
docker ps | findstr redis

# 检查端口
netstat -ano | findstr ":6379"

# 测试连接
docker exec -it <redis容器名> redis-cli ping
# 应返回 PONG
```

### 8.3 PDF 解析失败

```bash
# 检查 data/ 目录是否有 PDF 且不为空
dir data\

# 检查解析输出
dir mineru_output\

# 查看日志
type logs\app.log | findstr "error\|fail\|exception"
```

### 8.4 回答质量不佳

1. **查看调试信息**：在回答下方展开"调试信息"，检查命中的片段是否正确
2. **检查解析结果**：查看 `mineru_output/*_chunks.json` 确认 PDF 内容被正确提取
3. **切换检索模式**：尝试从"混合检索"切换到"BM25 检索"或"向量检索"
4. **补充规则**：如需新增特定问题的处理规则，修改 `utils/llm_engine.py` 中的 `_extract_answer_from_context` 方法

### 8.5 知识点：回答来源判断

| 调试信息中的检索模式 | 含义 |
|---------------------|------|
| `metadata` | 直接来自文档元数据（最快） |
| `long_term_memory` | 来自 Milvus 长期记忆 |
| `hybrid`/`bm25`/`vector` | 来自 PDF 检索 + LLM 生成 |
| 兜底文本 | 离线规则抽取结果 |

### 8.6 端口被占用

如果 8502 端口被占用：

```bash
.venv\Scripts\python.exe -m streamlit run app.py --server.port 8503
```
