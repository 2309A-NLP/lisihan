# PDF招股说明书智能问答系统技术文档

工单编号：人工智能 NLP-RAG-图像内容解析及检索优化

## 1. 项目概述

本项目面向招股说明书 PDF 构建智能问答系统，当前保留并整合了以下能力：

- PDF 正文、表格、图片/页面渲染解析
- BM25 + Milvus 向量检索 + RRF 融合检索
- 精确问题 BM25 快速路径
- 固定元数据直答
- 负向问题处理
- 多模态图片问题回答
- Redis 短期对话展示
- Milvus 长期优质问答记忆
- 工单问题批量评估与 JSON 结果输出

## 2. 系统入口

- `main.py`：统一启动入口，支持 `web` 和 `cli` 模式
- `app.py`：Streamlit 前端
- `test_工单问题.py`：工单问题批量测试脚本，输出 `工单问题测试结果.json`
- `run_mineru_wsl.py`：MinerU/WSL 解析入口，供主流程在缺少 MinerU 缓存时调用

## 4. 核心流程

1. 从 `data/` 读取 PDF。
2. 主流程优先读取或调用 MinerU，并把项目解析 JSON 写入 `mineru_output/`。
3. `RAGEngine.initialize_project_knowledge_base()` 构建 BM25 索引，并刷新文档元数据缓存。
4. 用户问题先经过问题分类、查询改写和 PDF 选择。
5. 固定字段、负向问题、力源表格规则、多模态图片问题优先走专用路径。
6. 普通问题进入混合检索；精确问题默认跳过向量检索以降低响应时间。
7. 回答优先使用规则抽取；必要时调用 LLM；不可用时使用离线兜底。
8. 答案经过质量校验，不可靠时触发重试或返回无答案提示。

## 5. 关键模块

### 5.1 `src/rag_engine/`

- `engine.py`：组合各 mixin，初始化解析器、检索器、LLM、图片解析器和元数据缓存。
- `initializer.py`：知识库初始化。
- `answering.py`：问答主流程、流式回答、批量回答。
- `context.py`：检索上下文构建与质量重试上下文。
- `metadata.py`：元数据直答、准确率估算、力源表格和实体抽取入口。
- `multimodal.py`：工单图片问题识别、图片选择、Redis 多模态缓存。
- `cache.py`：答案缓存与负向兜底响应。

### 5.2 `src/retriever/`

- `hybrid.py`：HybridRetriever 主类。
- `query.py`：分词、查询扩展、关键词加权、精确问题识别。
- `vector.py`：Milvus 向量检索。
- `fusion.py`：RRF 融合。
- `cache.py`：检索结果 LRU 缓存。

### 5.3 `pdf_parser/`

- `parser.py`：PDFParser 主类。
- `text_extractor.py`：PyMuPDF 文本抽取。
- `table_extractor.py`：pdfplumber 表格抽取。
- `visual_extractor.py`、`visual_detection.py`、`visual_render.py`：图片、图表、表格区域检测与渲染。
- `chunk_merger.py`：文本/表格合并与组合切块。
- `metadata_extractor.py`：法定代表人、注册资本等固定字段抽取。

### 5.4 `utils/llm_engine/`

- `engine.py`：LLMEngine 组合类。
- `generation.py`：在线 LLM 调用、流式输出、无上下文回答。
- `local_answer.py`：离线抽取、答案本地化、后处理。
- `numeric.py`：金额、比例、注册资本等数值抽取。
- `text_tools.py`：文本清洗、句子切分、关键词扩展。
- `entities.py`：关键实体补全。

## 6. 主要配置

配置集中在 `src/config.py`，可由环境变量覆盖。

```python
PDF_DIR = "./data"
PDF_PARSE_BACKEND = "mineru"
MINERU_OUTPUT_DIR = "mineru_output"
PDF_PARSE_OUTPUT_DIR = "mineru_output"
MINERU_FALLBACK_TO_LOCAL = False
MINERU_REQUIRE_MARKDOWN = True
MINERU_BACKEND = "pipeline"
MINERU_MODEL_SOURCE = "modelscope"
PDF_CHUNK_STRATEGY = "combined"
IMAGES_EXTRACT_DIR = "mineru_output/images"

RETRIEVAL_BACKEND = "hybrid"
BM25_K = 6
VECTOR_K = 4
RRF_K = 30
FINAL_K = 3
SKIP_VECTOR_FOR_EXACT_QUERIES = True

REDIS_URL = "redis://localhost:6379/0"
MILVUS_URI = "http://localhost:19530"

LLM_MODEL = "mimo-v2.5-pro"
MULTIMODAL_MODEL = "mimo-v2.5"
ENABLE_ANSWER_CACHE = False
ENABLE_LONG_TERM_MEMORY_ANSWER = False
ENABLE_MULTIMODAL_REDIS_CACHE = True
```

MinerU 批量解析入口支持单个 PDF、多个 PDF 或目录：

```powershell
.\.venv\Scripts\python.exe run_mineru_wsl.py data --output-dir mineru_output
.\.venv\Scripts\python.exe run_mineru_wsl.py data\招股说明书1.pdf data\招股说明书2.pdf --output-dir mineru_output
```

默认会向 WSL 中传入 `MINERU_MODEL_SOURCE=modelscope`，并使用 `-b pipeline`，避免默认走 Hugging Face VLM 模型下载。

项目解析 CLI 会输出实际后端、Markdown 路径和 content_list 路径，便于确认主流程确实来自 MinerU。

## 8. 工单问题测试

`test_工单问题.py` 会执行 10 个验收问题，并生成：

```text
工单问题测试结果.json
```

JSON 包含：

- `total`
- `success_count`
- `results`
- `comparison`
- 每题 RAG 答案、纯 LLM 答案、检索模式、耗时、上下文命中数和评估分数

## 9. 清洗与维护说明

- 当前代码已按包结构拆分，不再使用旧的 `src/rag_engine.py`、`src/retriever.py`、`utils/llm_engine.py` 单文件形态。
- ChromaDB 相关实现已不在当前主流程中使用。
- MinerU 是当前主解析后端；`pdf_parser/` 负责把 MinerU 的 `.md` 和 `content_list` 适配成项目需要的 chunk JSON。
- 主流程默认要求 MinerU 同时生成 `.md` 和 `content_list.json`；缺少任一文件时会报错，不再静默降级为本地解析。
- `__pycache__/`、`.pytest_cache/`、日志和旧测试 JSON 都属于可重新生成文件，可在清理时删除。
- 对动态入口、CLI 工具和可选多模态/MinerU 辅助脚本应保守保留，避免影响现有功能。

## 10. 验收重点

- 固定字段问题能通过元数据直答。
- 军用领域收入、收入占比、上游/下游、技术标准、重要供应商等问题命中正确片段。
- 负向问题不臆造答案。
- 图片类工单问题能选择固定页面或渲染页面后调用多模态模型。
- Redis/Milvus 不可用时系统应降级，不影响基础 PDF 问答。
