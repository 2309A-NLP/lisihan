## 1. 系统概述

本项目是一个基于 **RAG（检索增强生成）** + **多模态视觉理解** 的 PDF 智能问答系统。在招股说明书 PDF 的文本问答基础上，新增了**图片内容解析**能力——系统能自动识别 PDF 中的组织结构图、市场增长图等图片，调用多模态大模型分析并回答问题。

**核心能力：**

- 📄 **PDF 解析**：MinerU（WSL）高精度解析 + PyMuPDF/pdfplumber 回退
- 🖼️ **多模态图片问答**：识别 PDF 中的图表/图片，通过多模态大模型分析回答
- 👁️ **视觉 PDF 解析**：检测图片区域、表格区域、页面渲染
- 🔍 **混合检索**：BM25 + Milvus 向量检索 + RRF 加权融合
- 🧠 **记忆系统**：Redis 短期对话记录 + Milvus 长期优质问答持久化
- 🎯 **精准回答**：元数据直答、规则抽取、多模态分析、LLM 生成多级策略
- 📊 **评估能力**：内置工单问题批量测试与对比分析
- 🌐 **Web 界面**：Streamlit 交互式页面

### 5.5 运行 MinerU 解析 PDF（可选但推荐）

**为什么要先运行 MinerU？**

MinerU 提供比普通 PDF 库更精确的解析——保留版面结构、准确识别表格、提取图片位置。问答系统4以 MinerU 作为主解析后端，默认要求 MinerU 输出。

**运行方式：**

```powershell
cd C:\Users\freedom\Desktop\问答系统4

# 解析整个目录
.\.venv\Scripts\python.exe run_mineru_wsl.py data --output-dir mineru_output

# 或者指定单个文件
.\.venv\Scripts\python.exe run_mineru_wsl.py data\招股说明书1.pdf --output-dir mineru_output
```

**参数说明：**

| 参数 | 说明 |
|------|------|
| `data` | PDF 文件或目录路径 |
| `--output-dir mineru_output` | 输出目录（默认） |
| `--model-source modelscope` | 模型来源（国内推荐 ModelScope） |
| `--backend pipeline` | MinerU 后端（默认 pipeline） |

**MinerU 输出结构：**

```
mineru_output/
├── 招股说明书1/
│   ├── auto/
│   │   ├── 招股说明书1.md              # Markdown 格式全文
│   │   └── content_list.json           # 结构化内容列表（含图片位置）
│   └── ...
├── 招股说明书1_chunks.json            # 项目所需的切块结果
├── 招股说明书1_metadata.json          # 项目所需的元数据
├── 招股说明书2/
│   └── ...
├── 招股说明书2_chunks.json
├── 招股说明书2_metadata.json
└── images/                            # 提取的图片（用于多模态问答）
    ├── 招股说明书2_p039_render.png    # 组织结构图（第39页）
    ├── 招股说明书2_p072_render.png    # IC市场增长图（第72页）
    └── ...
```

> **注意：** 主流程默认要求 MinerU 同时生成 `.md` 和 `content_list.json` 文件。缺少任一文件时会报错，不再静默降级为本地解析。

conda activate mineru

详细配置参见 `src/utils/wsl_mineru.py`。

## 7. 多模态图片问答

### 7.1 功能说明

多模态图片问答是问答系统4 的新增核心能力。当用户提问涉及 PDF 中的图表、结构图时，系统会：

1. 识别问题是否为图片类问题（通过关键词匹配，如"组织结构图""图中"等）
2. 从 `mineru_output/images/` 中找到对应的图片
3. 将图片发送给多模态大模型 `mimo-v2.5` 分析
4. 返回分析结果
5. 结果缓存在 Redis 中（1 小时 TTL），相同问题秒回

### 7.2 预置图片

| 图片 | 文件名 | 来源 | 说明 |
|------|--------|------|------|
| 🏢 组织结构图 | `招股说明书2_p039_render.png` | 招股说明书2 第39页 | 展示公司组织架构，可问"有几个部门""销售部下设几个处"等 |
| 📈 IC 市场增长图 | `招股说明书2_p072_render.png` | 招股说明书2 第72页 | 展示 2008 年中国 IC 市场应用结构与增长情况 |

**预置问题示例：**

- 「武汉力源信息技术股份有限公司的组织结构图中，大客户销售部下设几个销售处？名称是什么？」
- 「根据2008年中国IC市场应用结构与增长图，哪几个领域呈现负增长？」

        "page": 39,

        "title": "组织结构图",

## 9. 常见问题排查

### 9.1 MinerU 解析失败

**现象：** 系统启动时提示 MinerU 解析失败

**原因：** 问答系统4 默认以 MinerU 为主解析后端，且 `MINERU_FALLBACK_TO_LOCAL=false`（失败不回退本地）。

**解决办法：**

```powershell
# 方案一：先手动运行 MinerU 解析
.\.venv\Scripts\python.exe run_mineru_wsl.py data --output-dir mineru_output

# 方案二：启用本地回退（在 .env 中添加）
MINERU_FALLBACK_TO_LOCAL=true

# 方案三：切换为本地解析后端（在 .env 中添加）
PDF_PARSE_BACKEND=local
```

### 9.2 多模态图片问答无响应

**现象：** 问组织结构图问题但系统走普通检索

**排查步骤：**

1. 确认 `mineru_output/images/` 目录下存在图片文件：
   ```
   mineru_output/images/招股说明书2_p039_render.png
   mineru_output/images/招股说明书2_p072_render.png
   ```
2. 确认 `.env` 中 `MULTIMODAL_API_KEY` 配置正确
3. 检查问题是否包含关键词：
   - 组织结构图 → 需要包含"组织结构图""销售部""大客户销售部"等
   - IC 市场增长图 → 需要包含"IC市场""IC 市场""增长""应用结构"等
4. 检查多模态 API 是否可用（超时 60 秒，图片分析比文本慢）

### 9.3 Milvus 连接失败

**现象：** 长期记忆不可用，或文档索引失败

**解决办法：**

```powershell
docker ps | findstr milvus
docker logs <milvus容器名>
```

**关于 `REBUILD_MILVUS_ON_INIT`：**

该配置控制每次初始化时是否重建 Milvus 索引：
- `false`（默认）：保留已有索引，仅增量添加新文档
- `true`：每次启动时重建索引（适用于数据变化后）

### 9.4 小米 MiMo API 调用失败

**现象：** 回答为空或报错

**排查步骤：**

```powershell
# 测试 API 连通性
curl -X POST https://token-plan-cn.xiaomimimo.com/v1/chat/completions `
  -H "Authorization: Bearer $env:LLM_API_KEY" `
  -H "Content-Type: application/json" `
  -d '{\"model\":\"mimo-v2.5-pro\",\"messages\":[{\"role\":\"user\",\"content\":\"你好\"}]}'
```

### 9.5 其他常见问题

| 问题 | 排查方向 |
|------|---------|
| 知识库初始化失败 | 检查 `data/` 是否有 PDF、`mineru_output/` 是否有 `*_chunks.json` |
| Streamlit 端口被占用 | `netstat -ano \| findstr :8502` 后 `taskkill` |
| Redis 不可用 | `docker ps` 检查 Redis 容器，`redis-cli ping` 测试 |
| 嵌入模型加载失败 | 确认 `EMBEDDING_MODEL_PATH` 路径存在 |
| 回答跑偏 | 展开"查看检索片段"确认命中的 chunk 是否正确 |
| 多模态缓存问题 | 设置 `ENABLE_MULTIMODAL_REDIS_CACHE=false` 可临时关闭缓存 |
