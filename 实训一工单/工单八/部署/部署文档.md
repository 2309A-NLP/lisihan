## 3. 基础设施启动

### 3.1 Docker 方式（推荐）

```powershell
# 启动 Redis 和 Milvus
docker-compose up -d

# 验证服务状态
docker ps

# 预期输出应有：
# - redis:latest
# - milvusdb/milvus:latest
```

`docker-compose.yml` 内容：

```yaml
version: "3.8"
services:
  redis:
    image: redis:latest
    ports:
      - "6379:6379"
  milvus:
    image: milvusdb/milvus:latest
    ports:
      - "19530:19530"
```

### 3.2 Neo4j 启动（Windows）

```powershell
# 如果安装了 Neo4j Desktop，直接启动本地数据库
# 或使用 Docker：
docker run -d `
  --name neo4j `
  -p 7474:7474 -p 7687:7687 `
  -e NEO4J_AUTH=neo4j/graphrag2024 `
  neo4j:5
```

### 3.3 单独启动组件（无 Docker）

如果不想用 Docker，可单独启动：

- **Redis**：下载 Windows 版 Redis 并运行 `redis-server.exe`
- **Milvus**：建议使用 Docker，Windows 原生部署较复杂
- **Neo4j**：下载 Neo4j Windows 安装包，启动服务

系统支持两种 PDF 解析后端：

| 后端 | 配置值 | 说明 |

## 9. 常见问题

### 9.1 Streamlit 启动报错

```
ModuleNotFoundError: No module named 'streamlit'
```

**解决**：确保在项目 `.venv` 环境下运行，或执行 `pip install -r requirements.txt`。

### 9.2 Redis 连接失败

```
Redis connection error
```

**解决**：
1. 确认 Docker 已启动：`docker ps`
2. 确认 Redis 容器运行中
3. 或设置 `.env` 中 `REDIS_HOST=localhost`

### 9.3 Neo4j 不可用

系统会自动降级到内存图谱模式，不影响核心功能。日志中会提示 `graph_backend=memory`。

### 9.4 MinerU 解析失败

**解决**：
1. 确保 WSL 环境已安装 MinerU
2. 或在 `.env` 中切换 `PDF_PARSER_BACKEND=pymupdf`
3. 如已存在 `mineru_output/` 的输出文件，设置 `MINERU_REUSE_OUTPUT=true`

### 9.5 向量检索无结果

**解决**：
1. 检查 Milvus 服务状态
2. 系统会自动降级为仅 BM25 检索模式
3. 在 Web 界面切换检索模式为 "BM25检索" 验证
