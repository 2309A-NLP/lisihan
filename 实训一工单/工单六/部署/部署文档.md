## 1. 系统概述

本系统面向**招股说明书 PDF 文档**，构建智能问答系统，支持：

| 特性 | 说明 |
|------|------|
| **PDF 解析** | MinerU 引擎（支持文本 / OCR 模式），含表格提取和图片提取 |
| **混合检索** | BM25（关键词）+ Milvus（向量检索）+ RRF 融合 |
| **动态权重** | 根据问题类型（专有名词/数值/抽象）自动调整 BM25 与向量权重 |
| **多模态** | 支持图片内容的视觉问答（组织结构图、市场增长图等） |
| **多轮对话** | Session 管理 + 指代消解（Coreference Resolution） |
| **记忆机制** | Redis 短期记忆（最近 20 条）+ Milvus 长期优质问答记忆 |
| **LLM 接入** | 小米 MiMo API（OpenAI 兼容接口），支持多种模型选择 |
| **评估系统** | RAG vs 纯 LLM 对比评估，上下文相关性、忠实度、完整度评分 |
| **前端** | Streamlit Web 界面，支持检索策略交互式调参 |

## 5. 外部服务部署

### 5.1 Docker 安装（Windows）

1. 下载 Docker Desktop：[https://www.docker.com/products/docker-desktop/](https://www.docker.com/products/docker-desktop/)

3. 确保底部状态栏 Docker 图标为绿色（运行中）

### 5.2 Redis 启动

项目根目录已有 `docker-compose.yml`：

```yaml
version: "3.8"
services:
  redis:
    image: redis:latest
    ports:
      - "6379:6379"
  milvus:
    image: milvusdb/milvus:latest
    ports:
      - "19530:19530"
```

**启动命令：**

```powershell
# 在项目目录执行
docker compose up -d
```

**验证服务是否正常：**

```powershell
# 验证 Redis
docker compose ps
.\.venv\Scripts\python.exe -c "import redis; r=redis.Redis(); print(r.ping())"
# 输出 True 表示正常

# 验证 Milvus
.\.venv\Scripts\python.exe -c "from pymilvus import connections; connections.connect(); print('OK')"
```

**停用命令：**

```powershell

```

### 5.3 单独启动（无 Docker）

**Milvus 替代方案：**

如果 Milvus 不可用，系统会自动降级（仅使用 BM25 检索，跳过向量检索）。后台会记录警告日志，不影响核心问答功能。

## 6. PDF 解析引擎（MinerU）部署

系统支持两种 MinerU 运行模式：

### 6.1 Windows 本地安装

MinerU 在 Windows 上可通过 Conda 安装：

```powershell
# 安装 MinerU （需要 Conda）
conda create -n mineru python=3.10
conda activate mineru
pip install magic-pdf[full]==0.7.0 -i https://pypi.tuna.tsinghua.edu.cn/simple

# 下载模型（ModelScope 国内推荐）
pip install modelscope
wget https://github.com/opendatalab/MinerU/raw/master/scripts/download_models_huggingface.py -O download_models.py
python download_models.py
```

配置 `src/config.py` 或 `.env`：

```ini
PDF_PARSER_BACKEND=mineru
MINERU_BACKEND=pipeline
MINERU_METHOD=auto
MINERU_MODEL_SOURCE=modelscope
MINERU_DEVICE=cpu
```

### 6.2 WSL 模式（推荐）

如果已经配置了 WSL 环境，可以使用 WSL 模式运行 MinerU：

```ini
MINERU_BACKEND=pipeline
MINERU_METHOD=auto
MINERU_WSL_DISTRO=Ubuntu      # WSL 发行版名称
MINERU_CONDA_PREFIX=/home/li/miniconda3
MINERU_CONDA_ENV=base
MINERU_MODEL_SOURCE=modelscope
```

**WSL 方式解析 PDF：**

```powershell
.\.venv\Scripts\python.exe run_mineru_wsl.py data --output-dir mineru_output

# 或指定具体文件
.\.venv\Scripts\python.exe run_mineru_wsl.py data\招股说明书1.pdf data\招股说明书2.pdf --output-dir mineru_output
```

**分片解析（大 PDF 自动分页）：**

```powershell
.\.venv\Scripts\python.exe run_mineru_segmented.py data\招股说明书2.pdf --segment-pages 20 --device cpu
```

> MinerU 解析完成后，需要在 Streamlit 界面点击"重新构建索引"将解析结果加载到 Milvus 和 BM25 索引中。

当以下情况时需要重新构建索引：

1. 首次部署后
2. `data/` 目录中添加了新 PDF 文件
3. 修改了 PDF 解析参数
4. 清除了 MinerU 输出或 Milvus 数据

**Web 界面操作：**

在左侧面板点击「重新构建索引」按钮。

**命令行操作：**

```powershell
# 重新解析 PDF
.\.venv\Scripts\python.exe run_mineru_wsl.py data --output-dir mineru_output

# 然后重新运行 Streamlit，系统会自动检测并索引新数据
```

### 9.3 评估测试

Web 界面左侧面板点击「运行工单问题评估」按钮，系统会对预定义的 14 个问题执行完整的 RAG 评估，生成对比报告：

| 指标 | 说明 |
|------|------|
| 上下文相关性 | 检索结果与问题的相关程度 |
| 答案忠实度 | 答案是否忠实于检索到的上下文 |
| 答案完整度 | 答案是否完整覆盖了问题要点 |
| RAG 对比值 | RAG 答案相比纯 LLM 答案的提升幅度 |

## 10. 常见问题

### Q1: Streamlit 启动时报 `ModuleNotFoundError`

```
原因：虚拟环境未激活或依赖未安装完整
解决：
  .\.venv\Scripts\activate
  .\.venv\Scripts\pip.exe install -r requirements.txt
  .\.venv\Scripts\pip.exe install -r pdf_parser\requirements.txt
```

### Q2: 无法连接 Redis

```
错误：Redis 短期记忆不可用
原因：Redis 服务未启动
解决：
  docker compose ps       # 检查 Redis 是否运行
  docker compose up -d    # 启动 Redis
  或启动 Windows Redis 服务
```

### Q3: 无法连接 Milvus

```
错误：Milvus 连接失败
原因：Milvus 服务未启动
现象：系统自动降级为纯 BM25 检索，功能基本正常
解决：
  docker compose up -d
  或配置 SKIP_VECTOR_FOR_EXACT_QUERIES=true 减少对 Milvus 的依赖
```

### Q4: 知识库初始化失败

```
原因：PDF 解析或索引构建出错
解决：
  1. 检查 data/ 目录下是否有 PDF 文件
  2. 检查 MinerU 输出目录 mineru_output/ 是否存在
  3. 查看 logs/app.log 获取详细错误信息
  4. 尝试手动解析：python run_mineru_wsl.py data\招股说明书1.pdf
```

### Q5: Embedding 模型加载失败

```
原因：模型文件不存在或路径错误
解决：
  1. 确认 C:\Users\freedom\Desktop\专业\模型\bge-base-zh-v1.5 存在
  2. 或在 .env 中设置正确的 EMBEDDING_MODEL_PATH
  3. 参考 4.3 节下载模型
```

### Q6: LLM API 调用超时

```
原因：网络问题或 API 限流
解决：
  1. 检查 .env 中的 LLM_API_BASE_URL 是否可访问
  2. 检查 LLM_API_KEY 是否有效
  3. 增大 LLM_TIMEOUT（在 .env 中设置）
  4. LLM_CONTEXT_MAX_CHARS 减小可降低请求大小
```

### Q7: MinerU 解析失败

```
原因：MinerU 环境配置不正确
解决：
  1. 如果使用 WSL 模式，确认 WSL 中已安装 MinerU
  2. 设置 MINERU_METHOD=txt（纯文本模式）绕过 OCR
  3. 设置 MINERU_DEVICE=cpu 避免 GPU 兼容性问题
  4. 使用 run_mineru_segmented.py 分片解析大 PDF
  5. 查看完整错误输出：run_mineru_wsl.py data\xxx.pdf 2>&1
```

### Q8: 回答质量不佳

```
排查步骤：
  1. 检查检索片段（Web 界面展开"查看检索片段"）
  2. 尝试切换检索模式：混合 -> BM25 -> 向量
  3. 调整 BM25/向量权重
  4. 检查 LLM 模型是否合适（更换 LLM_MODEL）
  5. 运行工单评估对比 RAG 与纯 LLM 效果
```
