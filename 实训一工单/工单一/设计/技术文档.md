# PDF文档问答系统技术文档

工单编号：人工智能NLP-RAG-基于PDF文档的问答系统

## 1. 项目概述

本项目是一个面向 PDF 文档的智能问答系统，当前检索方案只保留 BM25 关键词检索，不再使用向量检索、混合召回、短期记忆和长期记忆。

系统提供两种入口：

1. `main.py`：命令行模式与 Web 模式启动入口
2. `app.py`：Streamlit 网页应用入口

## 2. 系统架构

系统采用“文档解析 -> BM25 索引构建 -> 检索召回 -> 回答生成”的流程。

### 2.1 入口层

- `main.py`：负责依赖检查、命令行演示、Web 应用启动
- `app.py`：负责 Streamlit 交互界面、问答展示与反馈

### 2.2 核心引擎层

- `src/rag_engine.py`：RAG 主流程编排
- `src/pdf_parser.py`：PDF 文档解析与分块
- `src/vector_store.py`：BM25 检索索引与召回
- `utils/llm_engine.py`：LLM 回答生成与离线兜底
- `utils/question_classifier.py`：问题分类与规则识别

### 2.3 支撑层

- `src/config.py`：统一配置管理
- `utils/logger.py`：日志输出
- `utils/evaluator.py`：评测统计

### 2.4 数据流

1. 用户将 PDF 放入 `data/`
2. `PDFParser` 读取 PDF 并切分为文本块
3. `VectorStore` 基于文本块构建 BM25 索引
4. 用户提问后，`RAGEngine` 先做问题分类
5. 系统执行 BM25 检索召回相关片段
6. `LLMEngine` 基于召回上下文生成答案
7. 结果直接返回，不保存短期或长期记忆

## 3. 技术选型

### 3.1 Python

项目主体语言为 Python，便于快速构建文档处理、检索和 Web 交互流程。

### 3.2 Streamlit

用于快速构建 Web 界面，适合问答演示、状态展示和交互反馈。

### 3.3 PyMuPDF

用于解析 PDF 文档正文，性能稳定，接口直接。

### 3.4 BM25

用于关键词检索，提升对明确关键词问题的召回能力。

### 3.5 OpenAI API（可选）

用于在线回答生成；当未配置 API Key 或客户端不可用时，系统使用本地离线兜底逻辑保证可运行。

## 4. 模块说明

### 4.1 PDF 解析

`src/pdf_parser.py` 负责：

- 扫描 `data/` 目录下的 PDF 文件
- 逐页提取文本
- 按 chunk size 与 overlap 分块
- 为每个 chunk 附加来源页码、文件名等元数据

### 4.2 BM25 检索

`src/vector_store.py` 负责：

- 将文本块分词
- 构建 BM25 索引
- 根据查询计算关键词相关性
- 返回排序后的文本片段

### 4.3 回答生成

`utils/llm_engine.py` 负责：

- 识别问题意图
- 构建 Prompt
- 调用 LLM 生成答案
- 在无法调用模型时启用本地离线回答逻辑

### 4.4 问题分类

`utils/question_classifier.py` 负责：

- 对特定题号做规则识别
- 区分数值类、百分比类、实体类问题
- 为检索与 Prompt 生成提供分类结果

## 5. 开发流程

### 5.1 环境准备

1. 创建 Python 虚拟环境
2. 安装 `requirements.txt` 中依赖
3. 配置 `.env` 或环境变量

### 5.2 文档接入

1. 将 PDF 放入 `data/`
2. 启动系统后初始化知识库
3. 确认 BM25 索引成功构建

### 5.3 联调流程

1. 先验证 PDF 解析是否正常
2. 再验证 BM25 检索是否正常
3. 再验证 LLM 回答生成
4. 最后验证网页交互

### 5.4 验收流程

1. 使用内置评测问题集进行批量问答
2. 对比 RAG 回答与纯 LLM 回答
3. 检查响应时间、命中上下文和对比分析结果

## 6. 配置项

主要配置集中在 `src/config.py`：

- `PDF_DIR`：PDF 文档目录
- `LLM_MODEL`：模型名称
- `OPENAI_API_KEY`：OpenAI 密钥
- `TOP_K_RETRIEVAL`：检索条数
- `BM25_TOP_K`：BM25 召回条数
- `RETRIEVAL_BACKEND`：检索方式，当前固定为 `bm25`

## 7. 运行方式

### 7.1 Web 模式

```bash
python main.py
```

### 7.2 命令行模式

```bash
python main.py --mode cli
```

## 8. 风险与说明

- 当前系统不依赖 Milvus 或 Redis
- PDF 解析质量受原始文档排版影响
- LLM 在线能力依赖外部接口配置
- 当外部能力不可用时，系统会退化为离线逻辑，保证基本可用
- 对比分析可在网页评估区、命令行评测和测试结果文件中查看
