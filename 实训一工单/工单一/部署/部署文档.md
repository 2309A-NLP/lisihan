## 1. 系统概述

本系统是一个面向 PDF 文档（招股说明书）的智能问答系统。用户将 PDF 放入 `data/` 目录后，系统自动解析、分块、构建 BM25 索引，然后通过自然语言问答返回答案。

### 1.1 架构总览

```
┌────────────────────────────────────────────────┐
│                  入口层                          │
│   main.py（入口/CLI/Web）── app.py（Streamlit）  │
├────────────────────────────────────────────────┤
│                  核心引擎层                      │
│   rag_engine.py  → 主流程编排                     │
│   pdf_parser.py  → PDF 解析 & 分块               │
│   vector_store.py → BM25 索引 & 检索             │
│   llm_engine.py  → LLM 回答生成 & 离线兜底        │
│   question_classifier.py → 问题分类              │
├────────────────────────────────────────────────┤
│                  支撑层                          │
│   config.py  → 统一配置     logger.py → 日志      │
│   evaluator.py → 评测统计                        │
└────────────────────────────────────────────────┘
```

### 1.2 数据流

```
用户放入 PDF → PDF解析分块 → 构建BM25索引
  → 用户提问 → 问题分类 → BM25检索召回 → LLM生成答案 → 直接返回结果
```

## 3. 快速安装（标准流程）

### 3.1 获取项目

将项目文件夹放置在目标路径下，例如：

```
C:\Users\<用户名>\Desktop\问答系统1\
```

后续所有命令均在项目根目录下执行。

### 3.2 创建虚拟环境

```bash
# Windows PowerShell / CMD
python -m venv .venv

# 激活
.venv\Scripts\activate
```

```bash
# Linux / macOS
python3 -m venv .venv

# 激活
source .venv/bin/activate
```

### 3.3 安装依赖

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

> **国内加速建议**：使用清华 PyPI 镜像
> ```bash
> pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
> ```

**依赖清单**（requirements.txt）：

| 包名 | 版本 | 用途 |
|------|------|------|
| streamlit | >=1.29 | Web 交互界面 |
| rank-bm25 | >=0.2.2 | BM25 关键词检索 |
| pypdf | >=3.17 | PDF 文本解析（兜底方案） |
| openai | >=1.3 | LLM API 调用 |
| pandas | >=2.1 | 数据处理 |
| numpy | >=1.24 | 数值计算 |
| tiktoken | >=0.5 | Token 计数 |
| python-dotenv | >=1.0 | 环境变量加载 |

> **注意**：`requirements_backup.txt` 是包含 MinerU 等扩展包的完整版本快照，标准部署只需安装 `requirements.txt`。

### 3.4 配置环境变量

项目根目录下有 `.env` 文件，复制以下内容并填写：

```ini
# .env 文件
LLM_PROVIDER=siliconflow
LLM_API_BASE_URL=https://api.siliconflow.cn/v1
SILICONFLOW_API_KEY=sk-你的API密钥
LLM_MODEL=deepseek-ai/DeepSeek-V4-Flash
```

**说明**：

- **`LLM_API_BASE_URL`**：默认使用 SiliconFlow 的 API 地址。如需使用 OpenAI，改为 `https://api.openai.com/v1`
- **`SILICONFLOW_API_KEY`**：从 [SiliconFlow 官网](https://siliconflow.cn) 注册获取
- **`LLM_MODEL`**：支持所有 OpenAI 兼容接口的模型名
- 若不想配置在线 LLM，系统会自动降级为离线本地回答，保证基本功能可用

### 3.5 准备 PDF 文档

将招股说明书等 PDF 文件放入 `data/` 目录：

```
C:\Users\<用户名>\Desktop\问答系统1\data\
   └── 招股说明书1.pdf
```

> 系统启动时会自动扫描 `data/` 目录下的所有 PDF 文件。

## 4. 配置文件详解

### 4.1 `.env` 环境变量

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `LLM_PROVIDER` | `siliconflow` | LLM 提供商名称 |
| `LLM_API_BASE_URL` | `https://api.siliconflow.cn/v1` | API 端点 |
| `SILICONFLOW_API_KEY` | `""` | API 密钥 |
| `LLM_MODEL` | `deepseek-ai/DeepSeek-V4-Flash` | 模型名称 |

### 4.2 `src/config.py` 配置项

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `RETRIEVAL_BACKEND` | `bm25` | 检索方式（固定 BM25） |
| `COLLECTION_NAME` | `pdf_documents` | BM25 索引名称 |
| `TOP_K_RETRIEVAL` | `4` | 最终召回条数 |
| `BM25_TOP_K` | `10` | BM25 取 Top-K 条 |
| `PDF_DIR` | `./data` | PDF 存放目录 |
| `PDF_PARSER_BACKEND` | `mineru` | PDF 解析器（`mineru`/`pymupdf`） |
| `CHUNK_SIZE` | `1000` | 文本分块大小（字符数） |
| `CHUNK_OVERLAP` | `120` | 分块重叠大小 |

### 4.3 `config.json` MinerU 配置

| 配置项 | 说明 |
|--------|------|
| `apply_ocr` | 是否启用 OCR（默认 false） |
| `apply_table` | 是否提取表格（默认 true） |
| `apply_formula` | 是否提取公式（默认 false） |
| `layout_model` | 布局模型（默认 `doclayout_yolo`） |

```bash
# 激活虚拟环境后

```

```
└── [运行工单问题评估] 按钮

主聊天区：
├── 输入框 → 输入问题
├── 回答显示 → 含调试信息展开
├── 时间指标 → 检索/查询/生成时间
└── 反馈按钮 → 有帮助 / 需改进
```

### 5.2 命令行模式（批量评测）

```bash
python main.py --mode cli
```

输出示例：

### 5.3 生成评估报告

```bash
# 离线模式（无需API Key，使用本地兜底）

# 在线模式（使用 .env 中配置的 LLM）
python generate_pdf_qa_report.py --online-llm
```

输出文件位于 `outputs/` 目录：

- `pdf_qa_comparison_report_YYYYMMDD_HHMMSS.md` — Markdown 格式报告
- `pdf_qa_comparison_YYYYMMDD_HHMMSS.json` — JSON 格式明细

报告包含：整体指标、每道题的 RAG 答案与纯 LLM 答案对比、综合评分。

## 6. 高级部署：MinerU PDF 解析（Windows + WSL）

### 6.1 适用场景

需要高质量提取 PDF 中的表格、公式、复杂排版的场景。

### 6.2 安装 WSL MinerU

#### 步骤 1：安装 WSL

Windows PowerShell（管理员）：

```powershell
wsl --install -d Ubuntu
```

#### 步骤 2：安装 Miniconda（WSL 内）

```bash
# 进入 WSL
wsl

# 下载 Miniconda
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
bash Miniconda3-latest-Linux-x86_64.sh -b -p ~/miniconda3
~/miniconda3/bin/conda init
exit  # 重新登录 WSL
```

#### 步骤 3：安装 MinerU（WSL 内）

```bash
conda create -n mineru python=3.10 -y
conda activate mineru
pip install magic-pdf[full] -i https://pypi.tuna.tsinghua.edu.cn/simple

# 下载模型权重
wget https://github.com/opendatalab/PDF-Extract-Kit/raw/main/models/Layout/doclayout_yolo_docstructbench_imgsz1280_2501.pt
```

#### 步骤 4：配置 MinerU 模型文件

将模型文件放到项目的 `PDF-Extract-Kit/models/` 目录下对应的子目录中：

```
PDF-Extract-Kit/models/
├── Layout/       → doclayout_yolo_docstructbench_imgsz1280_2501.pt
├── MFD/
├── MFR/
└── TabRec/
```

可使用以下脚本自动下载：

```bash
python download_model.py
```

如果自动下载失败，可手动从 [ModelScope](https://modelscope.cn/models/opendatalab/PDF-Extract-Kit/files) 下载。

### 6.3 配置 MinerU 参数

在 `.env` 中配置 WSL MinerU 参数：

```ini
# MinerU 配置
PDF_PARSER_BACKEND=mineru
MINERU_CONDA_PREFIX=/home/li/miniconda3
MINERU_OUTPUT_DIR=./mineru_output
MINERU_METHOD=auto
MINERU_USE_CACHE=1
MINERU_WSL_DISTRO=Ubuntu
```

**参数说明**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `PDF_PARSER_BACKEND` | `mineru` | 解析器选择：`mineru` / `pymupdf` / `auto` |
| `MINERU_CONDA_PREFIX` | `/home/li/miniconda3` | WSL 中 MinerU conda 环境路径 |
| `MINERU_OUTPUT_DIR` | `./mineru_output` | MinerU 解析结果缓存目录 |
| `MINERU_METHOD` | `auto` | MinerU 调用方式 |
| `MINERU_USE_CACHE` | `1` | 是否使用缓存（重复解析同一 PDF 时跳过） |
| `MINERU_WSL_DISTRO` | `Ubuntu` | WSL 发行版名称（多发行版时指定） |

### 6.4 切换解析器

根据需求可灵活切换：

```ini
# 优先 MinerU，失败自动降级为 PyMuPDF（推荐）
PDF_PARSER_BACKEND=auto

# 强制使用 MinerU
PDF_PARSER_BACKEND=mineru

# 只使用 PyMuPDF（无需 WSL）
PDF_PARSER_BACKEND=pymupdf
```

### 6.5 测试 MinerU 集成

```bash
# 在 Windows 项目目录下执行
.venv\Scripts\python.exe examples\parse_pdf_with_mineru_wsl.py data\招股说明书1.pdf
```

正常输出：

```
MinerU markdown saved to: mineru_output/招股说明书1/auto/招股说明书1.md
Parsed 2267 chunks
```

## 7. 验收与评测

### 7.1 内置评测题

系统内置 **10 道评测题**，覆盖以下类型：

| 类型 | 题数 | 示例 |
|------|------|------|
| 数值型 | 3 | "军用领域收入分别是多少" |
| 百分比型 | 1 | "收入占主营业务收入的比重是多少" |
| 实体型 | 6 | "法定代表人是谁" / "参与制定了哪个技术标准" |

### 7.2 验收指标

| 指标 | 说明 |
|------|------|
| 上下文相关性 | 召回片段与问题的匹配程度（越高越好） |
| 答案忠实度 | 答案是否可被召回片段支撑（越高越好） |
| 答案完整度 | 答案是否覆盖了问题的所有方面 |
| 综合评分 | 上述指标的综合加权 |
| RAG 对比值 | RAG 答案相对于纯 LLM 答案的信息增益 |

### 7.3 运行验收

```bash
# 方式 1：Web 界面验收
python main.py
# 在左侧面板点击 → 运行工单问题评估

# 方式 2：命令行验收
python main.py --mode cli

# 方式 3：生成报告
python generate_pdf_qa_report.py
```

## 8. 常见问题排查

### 8.1 虚拟环境激活失败

```bash
# Windows - 执行策略限制
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
.venv\Scripts\activate
```

### 8.2 知识库未初始化

启动后页面提示"知识库未初始化"：

```bash
# 检查 data/ 目录下是否有 PDF 文件
ls data/

# 检查 PDF 文件不为空
# 在 Streamlit 左侧面板点击 [重新解析并构建 BM25 索引]
```

### 8.3 LLM API 调用失败

表现：回答返回"根据当前知识库，暂时没有找到足够相关的信息"（离线兜底）

```bash
# 检查 .env 中的 API Key 是否正确
# 确认 API BASE URL 是否可以访问
# 检查网络是否通畅（国内环境可能需要代理）
```

### 8.4 MinerU 解析失败

```bash
# 确认 WSL 已安装且 Ubuntu 正常运行
wsl --list --verbose

# 确认 MinerU conda 环境存在
wsl ~/miniconda3/bin/conda env list

# 降级为 PyMuPDF 兜底
# 修改 .env: PDF_PARSER_BACKEND=pymupdf
```

### 8.5 端口被占用

默认端口 8502 被占用时，修改启动命令：

```bash
python -m streamlit run app.py --server.port 8503 --server.address localhost
```

### 8.6 回答质量不佳

- 更换更明确的问题表达
- 确认 PDF 内容本身是否清晰（扫描件建议使用 MinerU + OCR）
- 调整 `TOP_K_RETRIEVAL` 和 `BM25_TOP_K` 参数（config.py）
- 检查召回片段中是否包含正确答案（可在 Web 界面展开"查看检索片段"）
