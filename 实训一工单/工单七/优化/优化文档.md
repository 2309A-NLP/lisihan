### 9.1 MetadataCache — 多公司元数据路由

**文件：** `src/cache/metadata_cache.py`（全新）

**问题背景：** 问答系统6 的元数据仅支持单公司（公司名/法定代表人等存储在 `document_metadata` 单一字典中）。工单七新增了 9 家金融公司的年报，需要按公司名路由到不同元数据。

**优化方案：** 新建 `MetadataCache` 类，替代原来散落在 `PDFParser` 中的元数据逻辑：

```
document_metadata_by_company = {
    "武汉兴图新科电子股份有限公司": {company_name, legal_representative, ...},
    "武汉力源信息技术股份有限公司": {company_name, total_shares, post_issuance_ratio, control_related_party, ...},
    "中国平安保险（集团）股份有限公司": {company_name, legal_representative, ...},
    ...
}
```

**智能路由逻辑：**

```python
def _select_document_metadata(self, question: str) -> Dict[str, str]:
    # 1. 提取问题中的公司实体
    # 2. 按 company_name 匹配
    # 3. 特殊处理"力源信息""兴图新科"等别名
    # 4. 不匹配时返回默认元数据
```

**支持的回答类型（工单七扩展）：**

| 问题类型 | 触发词 | 元数据字段 |
|---------|-------|-----------|
| 法定代表人 | "法定代表人" | `legal_representative` |
| 注册资本 | "注册资本" | `registered_capital` |
| 成立日期 | "成立日期"/"成立时间" | `establishment_date` |
| 注册地址 | "注册地址"/"注册地" | `registered_address` |
| 公司名称 | "公司名称" | `company_name` |
| 发行股数+比例 | "本次发行股数"+"比例" | `total_shares` + `post_issuance_ratio` |
| 存在控制关系 | "存在控制关系" | `control_related_party` + share + relation |
| 不存在控制关系 | "不存在控制关系" | `non_control_related_parties` |

**代码位置：** `cache/metadata_cache.py` → `_metadata_answer()`，`answering.py` 中 `ask()` 方法第 422 行调用

### 9.2 MultimodalTableExtractor — 多模态表格提取

**文件：** `src/multimodal/multimodal_table_extractor.py`（全新）

**问题背景：** MinerU 解析 PDF 时表格转为 Markdown，但复杂表格（跨页表格、合并单元格、含图片的表格）可能丢失结构信息。年报中有大量财务数据表格。

**优化方案：** 使用多模态视觉模型直接识别和提取表格：

**流程：**

```
PDF → 页面渲染为图片 (2x zoom) 
    → 逐页调用视觉模型进行表格检测 (TABLE_DETECTION_PROMPT)
    → 返回每页中表格的 bbox (百分比坐标)
    → 裁剪表格区域为独立图片
    → 跨页表格自动拼接 (continues_to_next / continues_from_previous)
    → 调用视觉模型提取 Markdown 格式 (TABLE_EXTRACTION_PROMPT)
    → 输出 tables.json
```

**关键 Prompt：**

- **检测：** `"找出页面中的所有表格区域"` → 返回 `{"has_table": true, "tables": [{table_id, bbox_percent, is_partial, continues_from_previous, continues_to_next}]}`
- **提取：** `"逐行读取所有数据，输出为Markdown表格格式"`

**跨页拼接：** `group_cross_page_tables()` 根据 `continues_from_previous`/`continues_to_next` 标志，将跨页的表格拼接为一张完整图片，再统一提取。

**图像拼接：** `stitch_table_group()` 使用 Pillow 将多页裁剪图垂直拼接为一图。

**完整结果：**

```json
{
  "source_file": "xxx.pdf",
  "page_images": [...],
  "regions": [...],
  "tables": [{"table_index": 1, "pages": [10,11], "image_path": "...", "markdown": "|...|"}]
}
```

**代码位置：** `multimodal/multimodal_table_extractor.py` → `MultimodalTableExtractor`

### 9.5 select_pdf 策略升级

**问题背景：** 工单六的 `select_pdf()` 总是返回一个具体的 PDF 文件名。对于跨文档对比问题（如"分析这些银行和保险公司的共同策略"），限制了检索范围。

**优化方案：** `select_pdf()` 返回类型改为 `str | None`：

- 匹配到已知公司 → 返回对应 PDF 文件名（精确限定）
- 未匹配任何公司 → 返回 `None`（不限 PDF，搜索全部文档）

**代码位置：** `rag_engine/metadata.py` → `select_pdf()` → 委托 `processing/query_rewriter.py`

> **总结：** 工单七相比工单六的主要演进方向是 **多公司支持**（MetadataCache、9 家年报、select_pdf 不限范围）和 **多模态表格**（MultimodalTableExtractor）。核心架构保持一致，新增模块均为独立扩展，不影响原有功能。
