## 1. 系统概述

本系统面向 **招股说明书 PDF** 和 **金融行业年报 PDF** 文档，构建智能问答系统。

### 1.1 版本演进

| 工单 | 新增能力 | 文档数量 |
|------|---------|---------|
| 工单一至六 | 招股说明书问答（BM25+向量+RRF） | 2 本（兴图新科、力源信息） |
| **工单七** | **+ 金融年报支持、多模态表格、MetadataCache** | **11 本（+9 家金融公司）** |

### 1.2 核心特性

| 特性 | 说明 |
|------|------|
| **PDF 解析** | MinerU 引擎（文本/OCR），含表格提取和图片提取 |
| **混合检索** | BM25 + Milvus 向量 + RRF 融合 |
| **动态权重** | 按问题类型自动调整 BM25/向量比例 |
| **多模态** | 图片内容视觉问答 + **多模态表格检测与提取** |
| **多轮对话** | Session 管理 + 公司指代消解 |
| **记忆机制** | Redis 短期记忆 + Milvus/MemoryFile 长期记忆 |
| **LLM 接入** | 小米 MiMo API（OpenAI 兼容接口） |
| **多公司元数据** | **MetadataCache：按公司名自动路由元数据查询** |
| **评估系统** | RAG vs 纯 LLM 对比评估 |
| **前端** | Streamlit Web 界面，交互式检索调参 |

```powershell
.\.venv\Scripts\python.exe run_mineru_wsl.py data --output-dir mineru_output
```

```ini
# .env 中配置
MINERU_METHOD=auto           # auto / txt / ocr
MINERU_BACKEND=pipeline
MINERU_MODEL_SOURCE=modelscope
MINERU_REUSE_OUTPUT=true     # 已有结果时跳过解析（推荐）
MINERU_PROCESSING_WINDOW_SIZE=8   # 处理窗口大小
MINERU_API_MAX_CONCURRENT_REQUESTS=1  # 并发请求数
```

## 7. 多模态表格提取部署

多模态表格提取是工单七新增的独立功能模块，使用视觉 API 检测和提取 PDF 中的表格。

### 7.1 额外依赖

所有依赖已在 `requirements.txt` 中包含（`requests`, `Pillow`）。无需额外安装。

### 7.2 命令行使用

```powershell
# 对单个 PDF 执行多模态表格提取
.\.venv\Scripts\python.exe -m src.multimodal.multimodal_table_extractor "data\招股说明书2.pdf"

# 指定输出目录
.\.venv\Scripts\python.exe -m src.multimodal.multimodal_table_extractor "data\招股说明书2.pdf" --output_dir mineru_output/multimodal_tables

# 自定义 API 配置
.\.venv\Scripts\python.exe -m src.multimodal.multimodal_table_extractor "data\xxx.pdf" ^
    --base_url https://token-plan-cn.xiaomimimo.com/v1 ^
    --model mimo-v2.5 ^
    --zoom 2.0
```

### 7.3 输出说明

```
mineru_output/multimodal_tables/
├── 招股说明书2/
│   ├── pages/              # 每页渲染图
│   │   ├── page_0001.png
│   │   └── ...
│   ├── crops/              # 表格裁剪图
│   │   ├── page_0039_table_01.png
│   │   └── ...
│   ├── stitched/           # 跨页拼接图
│   │   ├── table_0001_p0039.png
│   │   └── ...
│   └── tables.json         # 最终结果（所有表格的 Markdown 文本）
```

### 7.4 性能说明

- 每页调用 1 次检测 API + 每个表格调用 1 次提取 API
- 渲染 zoom=2.0，适合文字密集的年报/招股书
- temperature=0.1 保证输出一致性


### 10.3 动态权重策略

| 问题类型 | 触发条件 | BM25:向量权重 |
|---------|---------|--------------|
| `proper_noun` | 匹配公司名、人名 | 0.80 : 0.20 |
| `numeric` | 包含"多少""金额"等 | 0.70 : 0.30 |
| `abstract` | 字数 > 20 且含"什么" | 0.40 : 0.60 |
| `default` | 其他 | 0.65 : 0.35 |

### 10.4 回答优先级

```
多模态图片方案 > 未披露预检 > 负向查询预检 > 负向查询处理
> 元数据直答 (MetadataCache) > 负向兜底 > 表格元数据
> 长期记忆 > 混合检索 + LLM 生成
```

## 12. 常见问题

### Q1: 初始化索引后文档片段为 0

```
原因：data/ 目录下无 PDF，或 MinerU 解析输出不存在
解决：
  1. 确认 data\*.pdf 存在（应该至少有 1 个 PDF）
  2. 检查 mineru_output/ 目录是否有 *_chunks.json
  3. 如果缺少解析结果，运行 run_mineru_wsl.py 重新解析
  4. 确认 MINERU_REUSE_OUTPUT=true（默认）可以跳过已解析的 PDF
```

### Q2: 无法连接 Milvus

```
现象：系统自动降级为纯 BM25 检索
解决：
  docker compose up -d   # 启动 Milvus
  或完全移除对 Milvus 的依赖进行纯 BM25 问答
```

### Q3: 回答不准确

```
排查步骤：
  1. Web 界面展开"查看检索片段"确认检索质量
  2. 尝试切换检索模式：混合 → BM25 → 向量
  3. 运行工单评估对比 RAG 与纯 LLM 效果
  4. 检查问题是否被路由到正确的 PDF（select_pdf 逻辑）
```

### Q4: 多模态表格提取失败

```
原因：API Key 无效或图片过大
解决：
  1. 确认 .env 中 MULTIMODAL_API_KEY 正确
  2. 检查网络是否能连接 API 地址
  3. WEB 页面图片 zoom 参数（默认 2.0，可改为 1.5）
  4. timeout 默认 60s，大 PDF 可能需要延长
```

### Q5: Embedding 模型加载失败

```
原因：模型文件不存在或路径错误
解决：
  1. 确认 C:\Users\freedom\Desktop\专业\模型\bge-base-zh-v1.5 存在
  2. 在 .env 中设置正确的 EMBEDDING_MODEL_PATH
```

### Q6: 启动内存不足

```
原因：11 本 PDF 的 BM25 索引占用内存
解决：
  1. 减少 BM25_K 和 VECTOR_K 值
  2. 增加 LLM_CONTEXT_MAX_CHARS 减少片段数
  3. 使用 32GB+ 内存的机器
```

### Q7: 测试运行时 PatchedRAGEngine 报错

```
原因：工程默认不使用 PatchedRAGEngine，Web 界面使用标准 RAGEngine
      标准 RAGEngine 的 select_pdf 可能无法路由年报问题
解决：在 Web 界面中手动选择 PDF（暂无此功能），或等待年报路由集成
```
