## 三、待优化的项目（按优先级排列）

### 🔴 高优先级

#### ❌ 1. API Key 明文泄露

**文件**：`react_agent.py:32`、`batch_test.py:16`

**问题**：两处代码中都硬编码了明文 API Key：
```python
API_KEY = "sk-joz...wyst"
```

**影响**：提交到 Git 即泄露。当前已使用的 Key 可能已被泄露。

**建议**：
```python
# 强制从环境变量读取
import os
API_KEY = os.environ.get("SILICONFLOW_API_KEY")
if not API_KEY:
    raise ValueError("请先设置环境变量 SILICONFLOW_API_KEY")
```

同时将 Key 写入 `启动智能体.bat`：
```bat
set SILICONFLOW_API_KEY=你的Key
```

#### ❌ 2. 无单元测试

**问题**：项目没有 `tests/` 目录，核心功能无自动化测试覆盖。

**影响**：无法确保 SQL 生成逻辑修改后不破坏已有功能。

**建议编写测试**：

| 测试目标 | 测试点 |
|----------|--------|
| `react_agent.py` 的 `extract_block()` | 各类标签提取 |
| `app.py` 的 `parse_question()` | 日期/行业/涨幅提取 |
| `app.py` 的 `query_stock_count()` | SQL 查询正确性（mock 数据库） |
| `app.py` 的 `format_date()` | 日期格式化 |
| `batch_test.py` 的 `quick_answer()` | 端到端流程（mock API） |

#### ❌ 3. 无请求频率限制

**文件**：`app.py:318-340`

**问题**：`/ask` 接口无速率限制，用户可连续快速发送请求。

**影响**：短时间内大量请求消耗 API Token，可能导致超额扣费或 API 限流。

**建议**：
```python
from functools import lru_cache
import time

_last_ask_time = {}

@app.route('/ask', methods=['POST'])
def ask():
    # 简易频率限制
    client_ip = request.remote_addr
    now = time.time()
    if client_ip in _last_ask_time:
        if now - _last_ask_time[client_ip] < 5:
            return jsonify({'answer': '操作太频繁，请稍后重试', 'type': '', 'error': 'rate_limit'})
    _last_ask_time[client_ip] = now
    # ... 原有逻辑
```

### 🟡 中优先级

#### ❌ 4. 单例连接非线程安全

**文件**：`react_agent.py:88-101`

**问题**：`_db_conn` 全局单例在并发请求下可能出现竞争（虽然 `check_same_thread=False`，但 SQLite 写操作互斥）。

**影响**：多用户同时查询时有小概率返回 `database is locked` 错误。

**建议**：
```python
# 使用线程本地存储
import threading
_local = threading.local()

def get_db():
    if not hasattr(_local, 'conn') or _local.conn is None:
        _local.conn = sqlite3.connect(DB_PATH, timeout=30)
        _local.conn.execute("PRAGMA journal_mode=WAL")  # WAL 模式允许多读一写
        _local.conn.execute("PRAGMA synchronous=NORMAL")
        _local.conn.execute("PRAGMA cache_size=10000")
    return _local.conn
```

#### ❌ 5. SQL 注入风险

**文件**：`app.py:164-171`

**问题**：`query_stock_count()` 和 `query_stock_list()` 使用 f-string 拼接 SQL 条件：
```python
query = f'''
    SELECT ...
    WHERE h."交易日" = ?
      AND i."一级行业名称" = ?
      AND ... * 100 {condition} ?
'''
```

虽然参数通过 ? 占位符传入，但 `condition` 参数直接拼接，理论上可注入。

**建议**：限制 `condition` 为白名单值：
```python
ALLOWED_CONDITIONS = {">", ">=", "<", "<=", "="}
if condition not in ALLOWED_CONDITIONS:
    condition = ">"
```

#### ❌ 6. 备用解析器行业名称映射不完整

**文件**：`app.py:38-45`

**问题**：`INDUSTRY_MAP` 只定义了 4 条映射规则：
```python
INDUSTRY_MAP = {
    "建筑材料": "建筑材料",
    "建筑": "建筑材料",
    "建材": "建筑材料",
    "综合金融": "综合金融",
    "金融": "综合金融",
}
```

数据库实际有更多一级行业（如非银金融、钢铁、有色金属等），用户说"非银金融"时无法正确映射。

**建议**：从数据库中动态获取行业列表：
```python
def get_all_industries():
    conn = get_db_connection()
    if not conn:
        return []
    cursor = conn.cursor()
    cursor.execute("SELECT DISTINCT 一级行业名称 FROM \"A股公司行业划分表\"")
    return [row[0] for row in cursor.fetchall()]
```

#### ❌ 7. 无日志系统

**问题**：项目使用 `print()` 输出日志，没有 `logging` 模块。

**影响**：
- 日志不可分级（无法区分 DEBUG/INFO/ERROR）
- 无日志轮转，运行久了控制台会丢失早期信息
- 批量测试数小时后无法回溯

**建议**：
```python
import logging
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(message)s",
    handlers=[
        logging.FileHandler("logs/fund_agent.log", encoding="utf-8"),
        logging.StreamHandler()
    ]
)
```

#### ❌ 10. 备用解析器不支持"成交量合计"等复杂查询

**文件**：`app.py:59-140`

**问题**：`parse_question()` 只提取 日期+行业+涨幅阈值，不支持成交量合计、涨停天数等复杂问题。

**影响**：Agent 失败时，备用解析器只覆盖约 20% 的问题类型。

**建议**：扩展 parse_question 支持更多 query_type：
```python
"涨跌幅最大": {"query_type": "max_change"},
"成交量合计": {"query_type": "total_volume"},
"涨停天数": {"query_type": "limit_up_days"},
```

#### ❌ 11. 前端无超时提示

**问题**：前端 `fetch('/ask')` 无超时设置，LLM 调用慢时用户看不到反馈。

**建议**：
```javascript
const controller = new AbortController();
const timeout = setTimeout(() => controller.abort(), 120000); // 2分钟
try {
    const resp = await fetch('/ask', {
        method: 'POST',
        body: JSON.stringify({question}),
        signal: controller.signal,
    });
} catch (err) {
    if (err.name === 'AbortError') {
        showError('请求超时，请重试');
    }

```

#### ❌ 12. ReAct Agent 无最大推理步数友好提示

**文件**：`react_agent.py:305-370`

**问题**：达到 `max_steps=8` 时返回 `【已达最大推理步数，无法给出答案】`，无中间步骤信息。

**建议**：返回已执行步骤的上下文，帮助用户理解 Agent 卡在哪个环节。
