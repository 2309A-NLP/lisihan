## 一、项目概述

文生图智能体是一个输入面部图像、输出三个角度（右转/端正/左转）并支持扩图（outpainting）的 AI 工具。核心方案采用火山引擎 Doubao API 进行云端推理为主，本地 Stable Diffusion 和 3D 关键点变形为降级备用的三重管线架构。提供命令行、Python API、Gradio Web UI、纯 Python Web UI 四种使用方式。

## 二、已做优化（8项）

### 1. API 方案迁移：SiliconFlow → 火山引擎 Doubao

| 项目 | 内容 |
|------|------|
| **背景** | 原使用 SiliconFlow 的 Qwen-Image-Edit API，需付费且不再可用 |
| **迁移目标** | 火山引擎 Doubao Seedream-4.5 图像生成模型 |
| **收益** | 迁移后 API 支持 image-to-image 编辑 + mask 编辑，功能更完整 |
| **代码位置** | `pipelines/api_rotation.py` — `ApiRotationPipeline` 类 |
| **关键实现** | 环境变量 `ARK_API_KEY` / `ARK_ENDPOINT_ID` / `ARK_BASE_URL` 实现配置与代码分离 |

### 2. 三重管线降级机制

| 层级 | 管线 | 依赖 | 速度 | 适用场景 |
|------|------|------|------|---------|
| 主方案 | `api_rotation.py` (Doubao API) | 无本地模型 | 10-30秒 | 有网络时默认使用 |
| 备用1 | `face_rotation.py` (SD+IP-Adapter) | diffusers 5-10GB | 5-15分钟 | API不可用且有CPU资源 |
| 备用2 | `face_3d_rotation.py` (3D关键点) | insightface | 2-5秒 | 前两者均失败时兜底 |

- 扩图同样实现 API 优先 → 本地 SD Inpainting 降级
- `face_agent.py` 中 `try/except` 捕获异常并自动降级

### 3. CPU 模式深度适配

| 优化项 | 说明 | 代码位置 |
|--------|------|---------|
| 强制 fp32 | CPU 不支持 fp16，统一使用 float32 | 各 pipeline 的 `__init__` |
| 注意力切片 | 必须在 `load_ip_adapter()` **之前**启用，否则 SlicedAttnProcessor 覆盖 IP-Adapter 处理器 | `face_rotation.py:119` |
| VAE 切片 | 降低峰值内存占用 | `face_rotation.py:85` |
| VAE 平铺 | 处理大图时避免 OOM | `face_rotation.py:87` |
| 多线程优化 | `torch.set_num_threads(min(8, cpu_count))` | 各 pipeline |
| DDIM 调度器 | 替代默认 PNDM，减少推理步数 | `face_rotation.py:94` |
| CUDA 禁用 | `CUDA_VISIBLE_DEVICES=""` 强制 CPU 运行 | `face_rotation.py:21` |

| 项目 | 内容 |

| 项目 | 内容 |
|------|------|
| **文件** | `app_gradio.py` |

### 6. API 配置环境变量化

- **前**: API Key 硬编码在代码中
- **后**: `config.yaml` 配置 + 环境变量覆盖（`ARK_API_KEY` / `ARK_ENDPOINT_ID` / `ARK_BASE_URL`）
- **安全收益**: 敏感信息不进入代码仓库

### 7. 镜像源支持

- `config.yaml` 中 `mirror.type: huggingface`（默认）或 `modelscope`（国内加速）
- 国内用户切换后模型下载速度从几小时降到几分钟

### 8. 错误处理和日志系统

- 每个管线都有 `try/except` 异常捕获 + 中文错误提示
- `logging.info` / `logging.warning` 记录运行细节
- `history.json` 持久化历史记录（最多50条）

## 四、优化优先级总览

```
阶段一（近期 1-2周）：GPU加速 + 批量处理 + 模型缓存
阶段二（中期 1个月）：异步API + 更多角度 + WebUI增强 + Docker化
```

### 建议迭代路线

1. **Phase 1** — 先上 GPU 加速（收益最大），配合批量处理和模型缓存复用，用户可直接获得 50-100 倍速度提升
2. **Phase 2** — 增加角度控制精度和 WebUI 交互体验，异步 API 优化等待体验
3. **Phase 3** — Docker 部署简化分发，视频帧扩展场景，质量评估保障输出稳定性
