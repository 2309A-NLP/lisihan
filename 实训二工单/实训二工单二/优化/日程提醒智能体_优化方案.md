## 二、待优化的项目（按优先级排列）

### 🔴 高优先级

#### ❌ 1. 数据库连接池缺失

**问题**：`MySQLConnector.get_connection()` 每次调用都创建新连接，未使用连接池。频繁请求下（如 `/reminders` 每 30 秒轮询）反复创建销毁连接。

**影响**：并发高时可能导致 MySQL 连接数超限、响应延迟增加。

**建议方案**：
```python
# 使用 PyMySQL 连接池
import pymysql
from pymysqlpool.pool import Pool

# 或升级为 SQLAlchemy
from sqlalchemy import create_engine
from sqlalchemy.pool import QueuePool

engine = create_engine(
    f"mysql+pymysql://{user}:{password}@{host}:{port}/{database}",
    poolclass=QueuePool,
    pool_size=5,
    max_overflow=10,
    pool_recycle=3600,
)
```

#### ❌ 2. N+1 查询问题

**问题**：`get_today_schedules()`、`get_due_schedules()`、`get_upcoming_schedules()` 都通过 `get_all_active_schedules()` 全量拉取后，再在 Python 层逐条过滤。

**影响**：日程数量超过 1000 条后性能急剧下降。

**建议方案**：
```sql
-- 按日期查询非循环日程（一次 SQL 搞定）
SELECT * FROM schedules
WHERE status = 1
  AND repeat_rule IS NULL
  AND DATE(scheduled_time) = %s

UNION ALL

-- 循环日程由 Python 过滤（这部分数据量通常较小）
SELECT * FROM schedules
WHERE status = 1
  AND repeat_rule IS NOT NULL
```

#### ❌ 3. 测试文件仅占位

**问题**：`tests/test_parser.py`、`tests/test_dao.py`、`tests/test_reminder.py` 三个文件全部为空 docstring，没有实际测试代码。

**影响**：没有自动化回归测试，修改代码风险高。

**建议**：为以下核心功能编写 pytest 测试：

| 测试目标 | 测试点 | 优先级 |
|----------|--------|--------|
| `utils/time_utils.py` | 中文数字解析、时段转换、循环计算、边界日期 | 🔴 |
| `agent/intent_parser.py` | 各意图识别、批量提取、确认/取消 | 🔴 |
| `db/schedule_dao.py` | CRUD、到期查询、提醒日志防重 | 🟡 |
| `agent/scheduler_agent.py` | 多轮对话流程、缺参数补全、二次确认 | 🟡 |

### 🟡 中优先级

#### ❌ 4. 热点数据未缓存

**问题**：`get_all_active_schedules()` 在 `/today`、`/reminders`、`/status` 中反复全表扫描。30 秒轮询下每分钟至少查 2 次全表。

**影响**：MySQL 磁盘 I/O 浪费、查询延迟。

**建议方案**：
```python
# 内存缓存，30 秒过期
import time

_schedule_cache = {"data": None, "expires": 0}
CACHE_TTL = 10  # 秒

def get_all_active_schedules_cached():
    now = time.time()
    if _schedule_cache["data"] and now < _schedule_cache["expires"]:
        return _schedule_cache["data"]
    data = self.get_all_active_schedules()
    _schedule_cache["data"] = data
    _schedule_cache["expires"] = now + CACHE_TTL
    return data
```

#### ❌ 5. 前端轮询无退避策略

**问题**：前端 `setInterval(30s)` 固定频率轮询 `/reminders`，浏览器切后台也不停。

**影响**：标签页不可见时浪费带宽和 CPU。

**建议方案**：
```javascript
// 使用 Page Visibility API 动态控制轮询
document.addEventListener("visibilitychange", () => {
    if (document.hidden) {
        clearInterval(reminderTimer);
        reminderTimer = setInterval(pollReminders, 60000); // 切到后台60秒
    } else {
        clearInterval(reminderTimer);
        reminderTimer = setInterval(pollReminders, 30000); // 前台30秒
    }
});
```

#### ❌ 6. 密码硬编码安全隐患

**问题**：`config.py` 第 20 行 `MYSQL_PASSWORD = "***"` 明文写在代码中。

**影响**：代码提交到 Git 后密码泄露风险。

**建议方案**：
```python
# 1. 环境变量
import os
MYSQL_PASSWORD = os.getenv("SCHEDULER_DB_PASSWORD", "fallback_password")

# 2. .env 文件
from dotenv import load_dotenv
load_dotenv()
MYSQL_PASSWORD = os.getenv("MYSQL_PASSWORD")
```

#### ❌ 7. reminders 轮询全表扫描

**问题**：`get_due_schedules()` → `get_all_active_schedules()` → 逐条 `calculate_occurrence()` + `has_reminder_log()`。

**建议方案**：在 `schedules` 表增加 `next_occurrence` 字段，定时更新后直接按字段查询：
```sql
ALTER TABLE schedules ADD COLUMN next_occurrence DATETIME DEFAULT NULL;
CREATE INDEX idx_next_occurrence ON schedules(next_occurrence);
```

#### ❌ 10. 时间解析边界情况

| 场景 | 问题 | 示例 |
|------|------|------|
| "凌晨12点" | 时段+12 处理 | 凌晨为 0:00 而非 12:00 |
| "十一点差五分" | "差五分"未支持 | 应解析为 10:55 |
| "每两个小时的频率" | 不支持非标准循环 | 每N小时的日程 |
| "12:30am/pm" | 英文格式不支持 | 12:30 → "12:30" 被当作时间而非具体时刻 |

#### ❌ 11. 提醒消息模板单一

**问题**：仅 3 个固定模板随机选择，无节假日/天气等上下文注入。

**建议**：
```python
TEMPLATES = [
    "⏰ {content} 的时间到啦！",
    "🔔 现在该处理：{content}",
    "📌 提醒：{content}",
    "⏱️ 别忘了：{content} 哦",
    "🎯 {content}，该行动了！",
]
```

#### ❌ 12. 未支持后台守护进程

**问题**：Toast 提醒依赖 Web 前端的 `/reminders` 轮询，必须保持浏览器打开。

**建议**：在 `web_app.py` 中启动后台 APScheduler 线程独立轮询（即使用户关闭浏览器也能收到弹窗）：
```python
from apscheduler.schedulers.background import BackgroundScheduler

scheduler = BackgroundScheduler()
scheduler.add_job(
    check_and_notify,
    'interval',
    seconds=REMINDER_POLL_SECONDS,
    id='reminder_check'
)
scheduler.start()
```

#### ❌ 13. 启动时无配置校验

**问题**：`main()` 中 `MySQLConnector().init_database()` 失败时直接抛异常退出，无友好提示。

**建议**：
```python
def main():
    try:
        MySQLConnector().init_database()
    except pymysql.err.OperationalError as exc:
        logger.critical("数据库连接失败，请检查 MySQL 服务是否启动：%s", exc)
        input("按 Enter 键退出...")
        return
    # ... 正常启动
```
